# 게임 상세 UI 메모

> 작성일: 2026-03-31
> 범위: `문자중계`, `라인업` 탭

## 배경
- 기존 게임 상세 탭은 모바일 스포츠 앱보다는 일반 카드 UI에 가까웠다.
- 사용자 레퍼런스 이미지는 방송 그래픽에 가까운 정보 밀도와 구조를 요구했다.
- 핵심 의도는 `검은 배경 + 얇은 divider + 비교형 명단 + 현재 상황 집중` 이다.

## 문자중계 방향

### 원하는 구조
- 상단 `현재 타석` hero
- 이닝 전환 chip
- 이벤트 feed 는 카드 모음보다 `방송형 moment list`
- 중요한 이벤트는 큰 문장 1개
- 투구별 detail 은 보조 로그 형태

### 반영 원칙
- `현재 타석` 카드에서 타자/상대투수/주자상황/BSO 를 먼저 본다
- event item 은 `회차`, `득점/교체/종료 여부`, `핵심 이벤트 텍스트`를 우선 노출한다
- pitch-by-pitch detail 은 lead event 아래 보조 줄로 붙인다
- 작은 기기에서는 participant 카드가 세로로 떨어져 overflow 를 피해야 한다

## 라인업 방향

### 원하는 구조
- 양팀을 좌우 2열 비교
- 섹션: `선발 라인업`, `불펜투수`
- 선수는 카드보다 명단/표에 가까운 형태
- 팀 로고/팀명/선발투수/타순이 빠르게 읽혀야 함

### 반영 원칙
- 상단 hero 에 양팀 로고와 팀명을 놓고 `VS` 중심 비교 구조를 만든다
- 각 팀 column 은 `선발`, `1~9번 라인업`, `불펜투수` 흐름으로 정리한다
- 선수 셀은 `번호`, `이름`, `포지션` 정도만 간결하게 보여준다
- 기존 field diagram/card-heavy 구조보다 명단 중심으로 단순화한다

## 시각 톤
- 배경: `#0F0F0F`
- 카드/패널: `#1A1A1A`, `#252525`
- divider: `#333333`
- 텍스트: 흰색/회색 위주
- 팀 컬러는 제목, 왼쪽 포인트, 배지 정도에만 제한적으로 사용

## 구현 메모
- `라인업`은 KBO `GetMatchPlayerList` 실패 가능성이 높아 fallback 이 필요하다.
- `문자중계`는 실시간 로그인 relay 가 막히면 summary relay fallback 으로 보여줘야 한다.
- 따라서 디자인보다 먼저 `빈 화면 없이 대체 데이터라도 보여주기`가 우선이다.

## 후속 확인 포인트
- 실기기에서 작은 높이에서 overflow 없는지
- 문자중계 event 텍스트가 2~3줄 이상 늘어날 때 리듬이 유지되는지
- 라인업 양팀 column 길이가 달라도 비교 구조가 무너지지 않는지
