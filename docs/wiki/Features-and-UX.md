# 기능과 UX

## 주요 사용자 흐름

응원팀 선택 → 홈에서 내 팀 경기 확인 → 경기 상세 → 스코어·중계·박스스코어·라인업 탐색이 기본 흐름입니다. 기록실은 팀을 선택한 다음 팀 선수와 기록을 불러옵니다.

| 화면 | 주요 내용 |
| --- | --- |
| 온보딩 | 10개 구단 선택, 시작 또는 나중에 선택 |
| 홈 | 내 팀 경기, 오늘 경기, 팀 기록과 순위 진입 |
| 경기 상세 | 스코어, 이닝 기록, 문자중계와 핵심 장면, 박스스코어, 라인업, 하이라이트 |
| 일정 | 날짜별 경기, 다음 경기, 예매처와 예매 오픈 안내 |
| 순위 | 시즌별 구단 순위 |
| 기록 | 시즌·팀·선수 탐색, 투수/야수 필터, 지표 가이드, 같은 팀·시즌 선수 비교 |
| 브리핑 | 경기·순위·기록 기반 데이터 요약 |
| 알림함 / 설정 | 알림 확인, 응원팀, 화면 모드, 알림 프리셋과 개별 설정 |

현재 코드의 모바일 하단 탐색은 홈·일정·기록·브리핑·설정 5개입니다. 넓은 화면 탐색에는 순위가 추가됩니다. 순위 route는 모바일에서도 사용할 수 있습니다. 정확한 route는 `app_router.dart`와 `main_scaffold.dart`를 확인합니다.

## 화면 원칙

- 첫 화면에서 야구 정보를 빠르게 읽을 수 있게 합니다.
- 응원팀 개인화를 우선하고 실제 구단 엠블럼을 사용합니다.
- 다크 스포츠 톤, Jua 기본 글꼴, 라이트/다크/시스템 모드를 유지합니다.
- 기본 모바일 검토 크기는 390×844이며 작은 화면과 큰 글자도 검증합니다.
- 미확정 점수와 미수집 기록을 0으로 표시하지 않습니다. H/E/B의 `null`은 미제공입니다.
- 오류·로딩·빈 상태를 구분하고 재시도 또는 다음 행동을 제공합니다.
- LIVE는 빨강, 액션은 파랑을 사용하며 색만으로 상태를 전달하지 않습니다.
- 앱 UI에는 이모지 텍스트를 사용하지 않습니다.

예매 오픈 시간은 홈팀 정책에 기반한 추정 안내일 수 있으므로 실제 예매처 정보를 확인하도록 합니다. 디자인 산출물과 구현 캡처는 중요한 근거지만, Figma 캔버스 수정이나 실제 운영 데이터 검증을 대신하지 않습니다.
