# 경기/마이팀 선수 기록 인사이트 기획

## 결론

가능하다. 다만 한 번에 모두 넣으면 데이터 신뢰도가 무너진다. `박스스코어/문자중계로 확정 가능한 경기 단위 인사이트`, `선수별 경기 로그가 필요한 연속 경기 인사이트`, `KBO/개인 통산 기준선이 필요한 역사적 인사이트`를 분리해서 가야 한다.

## 제품 방향

기능 중심 이름은 `기록 레이더`로 잡는다. 사용자가 앱을 열었을 때 “오늘 어떤 기록이 나올 수 있는지”, “어제 무슨 기록이 달성됐는지”, “내 팀 선수에게 역사적으로 의미 있는 순간이 있는지”를 한 번에 훑게 하는 피드다.

홈 정보 구조는 `마이팀 브리프`와 `KBO 브리프`를 분리한다. `마이팀 브리프`는 내 팀 중심의 오늘 할 일이고, `KBO 브리프`는 그날 리그 전체에서 놓치면 아쉬운 강한 정보를 요약하는 영역이다.

## 노출 위치

- 경기 상세 스코어 탭: 해당 경기에서 나온 기록 포인트 2~3개
- 홈 마이팀 브리프: 마이팀 경기 종료 후 가장 강한 1개만 quick item 후보
- 홈 KBO 브리프: 마이팀 브리프 바로 아래에서 그날 리그 전체 관전 포인트/강렬한 결과 3~5개 노출
- 홈 기록 레이더 섹션: `오늘 가능`, `어제 달성`, `이번 주 주목`을 가로 카드 또는 리스트로 노출
- 일정/경기 예정 상세: 해당 경기에서 달성 가능한 선수/팀 기록 후보
- 선수 상세: 이후 선수별 최근 경기 타임라인과 연결
- 기록실/선수 상세: 개인 통산, KBO 통산 순위, KBO 최초/최연소/최단 경기 같은 역사적 의미를 badge/timeline으로 노출

## 시간축 UX

| 경기/날짜 상태 | 섹션 제목 | 내용 | 예시 카피 |
|----------------|-----------|------|-----------|
| 경기 예정 | 오늘 달성 가능 | 경기 전 누적값 기준으로 threshold까지 가까운 기록 | `오늘 1안타면 개인 통산 1000안타` |
| 경기 중 | 진행 중인 기록 | live boxscore 기준으로 달성 임박/달성 상태 갱신 | `현재 2안타, 1개 남음` |
| 오늘 경기 종료 | 오늘 달성 | final boxscore 반영 후 실제 달성 기록 | `오늘 개인 통산 100홈런 달성` |
| 다음날 | 어제 달성 | 전날 final persistence 기준 성과 요약 | `어제 KBO 통산 TOP 10 진입` |
| 경기 없는 날 | 다음 경기 가능 | 다음 예정 경기 기준 후보를 미리 노출 | `다음 경기에서 2K면 1500탈삼진` |

홈 첫 화면의 기본 우선순위는 `마이팀 오늘 가능` → `마이팀 어제 달성` → `리그 전체 역사적 기록` → `일반 경기 인사이트`다.

## KBO 브리프

`KBO 브리프`는 마이팀 브리프 밑에 붙는 리그 전체 요약이다. 스코어 나열이 아니라 “오늘 KBO에서 뭐가 센가”를 보여준다.

| 날짜/경기 상태 | 브리프 제목 | 포함 정보 | 예시 |
|----------------|-------------|-----------|------|
| 경기 전 | 오늘의 KBO 관전 포인트 | 빅매치, 선발 매치업, 순위 싸움, 달성 가능 기록 | `1위 LG vs 2위 한화, 선두권 직접 맞대결` |
| 경기 중 | 지금 KBO에서 벌어지는 일 | 역전/대량 득점/무실점 진행/노히트 가능성/기록 임박 | `삼성 7회 6득점, 경기 흐름 뒤집음` |
| 경기 종료 직후 | 오늘의 KBO 요약 | 가장 강한 경기 결과, 선수 활약, 기록 달성, 순위 변동 | `KIA 12득점 대승, 올러 10K 무실점` |
| 다음날 오전 | 어제의 KBO 브리프 | 전날 확정 기록과 핵심 경기 3~5개 | `어제 KBO: 연장 끝내기, 통산 기록, 순위 변동` |
| 경기 없는 날 | 이번 주 KBO 포인트 | 다음 시리즈, 순위 경쟁, 달성 임박 기록 | `이번 주 선두권 3연전, 통산 100홈런 후보 2명` |

### KBO 브리프 카드 타입

| 타입 | 설명 | 예시 카피 | 근거 |
|------|------|-----------|------|
| 빅매치 | 순위/라이벌/연승 흐름이 강한 경기 | `선두권 직접 맞대결` | standings + schedule |
| 경기 흐름 | 역전, 대량 득점, 연장, 끝내기, 접전 | `9회말 끝내기 승리` | scoreboard + relay |
| 선수 활약 | 그날 가장 강한 타자/투수 활약 | `올러 6이닝 무실점 10K` | boxscore |
| 기록 레이더 | 오늘 가능/오늘 달성/어제 달성 | `오늘 1안타면 개인 통산 1000안타` | daily record snapshots |
| 순위 변동 | 1위 탈환, 공동 순위, 게임차 변화 | `KIA 3위와 0.5G 차` | standings before/after |
| 팀 흐름 | 연승/연패/스윕/시리즈 위닝 | `롯데 5연승` | team game log |

### KBO 브리프 우선순위

1. KBO 최초/최고/통산 milestone 달성
2. 끝내기/대역전/연장/노히트 임박 같은 경기 이벤트
3. 선두권/가을야구권 순위 변동
4. 마이팀과 직접 관련된 리그 이슈
5. 압도적 개인 활약
6. 오늘 달성 가능 기록

### KBO 브리프 UX

- 홈에서 마이팀 브리프 바로 아래에 `KBO 브리프` 제목으로 노출한다
- 기본은 3개, 확장 시 5개까지 보여준다
- 각 카드는 `왜 중요한지`가 한 줄에 보여야 한다
- 카드를 누르면 경기 상세, 선수 상세, 기록실, 순위 화면으로 이동한다
- 마이팀 브리프와 중복되는 내용은 KBO 브리프에서 우선순위를 낮춘다
- 데이터 근거가 약하면 `관전 포인트`, 근거가 확정되면 `달성/확정/승리` 같은 확정형 문구를 쓴다

## MVP 범위

P0는 UI 없이 검증만 한다.
- 샘플 종료 경기 10개에서 boxscore/relay parser가 같은 결론을 내는지 확인
- 인사이트마다 `source`, `evidenceText`, `confidence`, `hiddenReason`을 남긴다
- 근거가 없으면 노출하지 않는다

P1은 경기 상세만 한다.
- 후보 API: `GET /api/game/{gameId}/insights?teamId={teamId}&limit=3`
- 앱은 빈 응답이면 섹션을 숨긴다
- mock fallback 금지, snapshot/service 근거만 사용

P1.5는 홈 마이팀 브리프다.
- `/api/home` 안에 snapshot-only 결과 1개만 포함
- 홈에서 별도 인사이트 API fan-out 호출 금지
- live 경기 중에는 노출하지 않고 종료/저장된 경기 우선

P2는 선수 상세 확장이다.
- 선수별 game-log snapshot을 먼저 만든다
- `몇 경기 연속 안타`, `최근 5경기 OPS`, `최근 3경기 홈런 2개` 같은 흐름형 기록을 선수 상세에서 보여준다

P3는 역사적 기록 레이어다.
- `record_catalog`를 만든다: KBO 최초, 최연소, 최단 경기, 단일 경기 최고, 시즌/통산 milestone threshold
- 선수별 career total snapshot을 만든다: 경기 전 누적값, 경기 후 누적값, 시즌값, 통산값
- 판정은 `before < threshold <= after` 방식으로 한다. 예: 경기 전 99홈런, 경기 후 100홈런이면 `개인 통산 100홈런`
- KBO 최초/최고 기록은 자동 추정하지 않는다. 반드시 record catalog에 기준선과 출처를 가진 항목만 노출한다
- KBO 통산 순위 변화는 all-time leaderboard snapshot이 있는 지표부터 제한적으로 시작한다

P4는 일자별 기록 레이더다.
- 매일 새벽/경기 전 `daily_record_candidates`를 생성한다
- 경기 종료 후 `daily_record_achievements`를 생성한다
- 홈은 이 두 snapshot을 읽어 `오늘 달성 가능`, `어제 달성`, `마이팀 주목` 피드를 만든다
- 예정 경기는 예상 출전 가능성이 낮은 선수 기록을 과하게 노출하지 않는다. 라인업 발표 전에는 주전/선발 예정/최근 출전 선수 중심으로 제한한다
- 달성 가능 후보는 `threshold - beforeTotal`이 현실적인 단일 경기 달성 범위 안에 있을 때만 표시한다

## 기록 레이더 데이터 모델

| 데이터 | 용도 | 필수 필드 |
|--------|------|-----------|
| `record_catalog` | 최초/최고/최연소/구단 기록 기준선 | `recordId`, `scope`, `metric`, `threshold`, `source`, `rule`, `priority` |
| `player_career_daily` | 경기 전/후 개인 통산 비교 | `date`, `playerId`, `teamId`, `metricTotals` |
| `player_game_log` | 연속 경기/최근 흐름 판정 | `date`, `gameId`, `playerId`, `hits`, `homeRuns`, `rbi`, `strikeouts` |
| `all_time_leaderboard` | KBO 통산 순위 변화 판정 | `metric`, `rank`, `playerId`, `value`, `asOfDate` |
| `daily_record_candidates` | 오늘/다음 경기 달성 가능 후보 | `date`, `gameId`, `playerId`, `remaining`, `threshold`, `confidence` |
| `daily_record_achievements` | 오늘/어제 달성 기록 | `date`, `gameId`, `playerId`, `before`, `after`, `evidence` |
| `kbo_daily_brief` | 마이팀과 별개인 리그 전체 강한 요약 | `date`, `status`, `items`, `priority`, `route`, `evidence` |

## 후보 판정 원칙

- 개인 통산 후보: `0 < threshold - beforeTotal <= plausibleSingleGameMax`
- KBO 통산 순위 후보: 현재 순위권 바로 아래거나, threshold까지 남은 수치가 작을 때만 노출
- KBO 최초/최고 후보: catalog에 “오늘 달성 가능 조건”이 정의된 항목만 노출
- 연속 경기 후보: `player_game_log`로 직전 경기까지의 streak가 확인될 때만 노출
- 라인업 전 후보: 마이팀/스타 선수/선발 예정 투수 위주로 제한
- 라인업 후 후보: 실제 선발 라인업 포함 선수 우선
- KBO 브리프 후보: 같은 경기에서 여러 카드가 나오면 가장 강한 하나만 대표로 올리고 나머지는 상세 진입 후 노출

## 피드 우선순위

1. KBO 최초/최고/최연소/최단 달성 또는 달성 임박
2. KBO 통산 TOP 순위 진입/상승
3. 개인 통산 milestone
4. 구단 기록
5. 연속 경기/연속 타석/최근 흐름
6. 단일 경기 활약

## 역사적 기록 타입

| 타입 | 설명 | 노출 예시 | 필수 데이터 |
|------|------|-----------|-------------|
| 개인 통산 milestone | 선수 개인 누적 기록이 기준선을 넘는 순간 | `김도영 개인 통산 100홈런` | career total before/after |
| KBO 통산 ranking | KBO 전체 통산 순위권 진입/상승 | `통산 홈런 TOP 10 진입` | all-time leaderboard snapshot |
| KBO 최초 | 리그 역사상 처음 나온 조합/기록 | `KBO 최초 기록` | curated record catalog |
| KBO 최고/타이 | 단일 경기/시즌/통산 최고 또는 타이 | `한 경기 최다 타점 타이` | record catalog + 당일 기록 |
| 최연소/최단 경기 | 나이/출장 경기 수 기준 milestone | `최연소 100안타` | 생년월일, 데뷔일, 출장 경기 수 |
| 구단 기록 | 마이팀 팬에게 의미 있는 팀 내부 기록 | `KIA 구단 최다 타이` | team record catalog |

## UX 원칙

- 카드 제목은 짧게: `김호령 2연타석 홈런`
- 부제는 근거형: `문자중계 타석 결과 기준`
- 탭하면 근거 바텀시트: 해당 타석/박스스코어 라인 1~3개
- 확신 낮은 추정은 노출하지 않는다
- 한 경기당 같은 선수 카드가 너무 많이 뜨면 우선순위 높은 1개로 합친다
- 역사적 기록은 일반 경기 기록보다 우선순위를 높인다. 단, 출처/기준선 없는 `최초` 문구는 금지한다
- `오늘 달성 가능`은 기대감을 주되 확정처럼 말하지 않는다. `1개 남음`, `오늘 도전` 같은 표현을 쓴다
- `어제 달성`은 확정형으로 말한다. 단, final snapshot과 catalog evidence가 있을 때만 사용한다

## 리스크

- relay 텍스트는 KBO 사이트 문구 변화에 취약하다.
- 동명이인/대주자/대타가 섞이면 이름만으로 타석 연결이 흔들릴 수 있다.
- player_detail의 `recentGames`가 현재 비어 있어 경기 연속 기록은 별도 적재 파이프라인이 먼저다.
- KBO 최초/통산 기록은 잘못 말하면 신뢰도를 크게 잃는다. 공식 기록 페이지 또는 수동 검수 catalog 없이는 노출하지 않는다.
- all-time 기록은 현역/은퇴 선수, 리그명 변화, postseason 제외 여부 같은 기준 정의가 필요하다.
- 오늘 가능 후보는 출전하지 않으면 허수가 된다. 라인업 전/후 confidence를 분리해야 한다.
- “쫙 뜨는” 피드는 가치 있지만 과밀해질 수 있다. 홈은 3~5개, 기록실은 전체 리스트로 역할을 나눈다.
- 홈에 너무 많은 기록 카드를 넣으면 마이팀 경기/순위보다 시선이 분산된다.
