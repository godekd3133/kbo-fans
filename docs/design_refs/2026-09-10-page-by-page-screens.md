# KBO Fans 페이지별 시안 — 2026-09-10

이 문서는 홈 시안을 다른 페이지에 복제하는 문서가 아니라, 각 화면의 사용 목적과 첫 화면 우선순위를 고정하는 구현용 시안이다. 모든 화면은 390×844를 기준으로 잡고, 데이터가 없을 때 실제 값 대신 명시적인 미제공 상태를 표시한다.

## 공통 방향

- 배경은 `#0F0F0F`, 정보 surface는 `#171717`, 카드 surface는 `#1D1D1D`를 사용한다.
- 팀 색상은 전체 배경이 아니라 3px rail, 로고, 선택 테두리, 상태 표시에서만 사용한다.
- 일반 선택은 액션 블루, LIVE와 오류는 레드, 정상 완료는 그린으로 분리한다. 홈 알림 unread badge의 red는 새 알림 의미로만 사용한다.
- 제목은 `AppPageHeader`, 반복 정보는 `AppSurface`, 팀 표시는 `AppTeamIdentity`, 상태는 `AppStatusPill`을 우선 사용한다.
- 모든 주요 액션은 최소 44px 터치 영역을 갖고, 아이콘만 있는 버튼에는 semantic label과 tooltip을 붙인다.
- 현재 버전·변경점처럼 한 번에 읽어야 하는 정보 묶음은 하나의 semantics summary로 제공하고, 시각 텍스트의 중복 읽기는 제외한다.
- 하나의 시각적 선택/행동은 하나의 접근성 action node로만 노출한다. 내부 pressable을 별도 button으로 중복 노출하지 않으며, 요약 surface가 내부 동작을 대체할 때는 외부 summary node에 실제 tap action을 연결한다.
- 명시 label이 있는 공통 pressable은 semantic boundary를 만들어 부모 페이지 제목·설명과 action label이 섞이지 않게 한다.
- 예정 경기 score가 미제공이면 `0 : 0`을 실제 결과처럼 만들지 않고 팀 대 팀 `vs`와 예정 시각을 표시한다. 확인된 LIVE/FINAL 0:0은 실제 동점으로 구분한다.
- 탭 가능한 설정 섹션 row는 내부 `AppPressable` 하나가 button semantics와 tap action을 소유하며, 바깥에 또 다른 button semantics를 감싸지 않는다.
- 일정 월 헤더의 이전·다음·오늘 action도 동일한 단일 action node 규칙을 따른다.
- 홈 순위 preview row와 온보딩 팀 card도 동일한 단일 pressable 규칙으로 팀 상세 action과 selected 상태를 전달한다.
- 기록실 팀 상세의 뒤로 action도 동일한 단일 summary/action 규칙을 따른다.
- 온보딩 편집 모드의 뒤로 action도 동일한 단일 summary/action 규칙을 따른다.
- 공통 페이지 헤더는 action·eyebrow·title·subtitle을 explicit child semantics로 분리한다.
- 홈 header icon은 Tooltip뿐 아니라 실제 button semantics에도 읽을 수 있는 label과 tap action을 제공한다.
- 경기 상세 영상 mode chip은 일반 선택 action-blue와 selected semantics를 함께 제공한다.
- 기록실의 `마운드 체크` category는 action blue로 표시하고 경기 진행 상태의 LIVE red와 구분한다.
- 홈 헤더의 알림·검색 icon은 최소 44px 조작 영역을 유지하고, 실제 button semantics에 label과 tap action을 제공한다.
- 순위·기록실 팀 상세의 시즌 선택 surface는 최소 44px 높이로 유지한다.

## 페이지별 구현 기준

### 01–07 기본 탭

기본 탭은 헤더 높이와 페이지 좌우 여백을 통일한다. 홈만 score-first hero를 사용하고, 일정·순위·기록·브리핑·설정은 제목과 설명을 먼저 보여준 뒤 한 가지 핵심 작업으로 이어진다. 홈 헤더의 알림 아이콘은 미읽음 수가 있을 때만 red badge를 표시하고, 알림 저장·읽음 처리·알림함 복귀·앱 resume 뒤에도 현재 읽음 상태를 다시 반영한다. 각 탭의 빈 상태는 장식용 이미지보다 원인과 다음 행동을 먼저 보여준다.

### 08–11 경기 상세

경기 상세는 상단 scorebug와 탭을 고정된 읽기 기준으로 사용한다. 하위 탭은 동일한 팀·상태·이닝 정보를 반복해서 설명하지 않고, 탭이 바뀌어도 현재 경기의 정체성이 유지되도록 한다. LIVE 데이터가 없으면 `0:0`을 만들어내지 않고 `미확인` 또는 `집계중`을 사용한다.

라인업 탭은 `선발 라인업 → 선발 투수 → 최근 흐름/맞대결 비교` 순서를 고정한다. 비교 데이터가 있더라도 타순 확인을 첫 화면 아래로 밀지 않으며, 공개 전·오류·집계중 상태는 같은 위치에서 원인과 다음 행동을 보여준다.

박스스코어 LIVE context는 팀 요약 제목 옆에 `LIVE` pill을 두어 공식 박스스코어와 구분한다. 타수·안타가 아직 계산되지 않은 경우에는 `집계중`과 현재 확인된 타자·투수 수를 함께 보여주며, 공식 기록처럼 보이는 0을 만들지 않는다. 매칭된 선수 행은 요약 내용과 `선수 기록 보기` tap action을 하나의 접근성 제어로 제공한다.

경기 상세 상단 뒤로가기는 시각 버튼과 접근성 label/action을 하나의 노드로 합쳐, 브라우저·스크린리더에서 복귀 동작이 중복 탐색되지 않도록 한다.

### 12 알림함

알림함은 설정 화면과 역할을 섞지 않는다. 상단에는 보관 수·현재 표시 수·안 읽은 수를 놓고, 아래에서 필터와 타임라인을 제공한다. 알림이 없을 때는 “아직 없음”과 어떤 신호가 여기에 쌓이는지 한 문장으로 설명한다.

### 13–14 기록 상세

리더보드는 레드가 아니라 블루를 일반 선택색으로 사용하고, 공식 출처와 앱 계산 지표를 배지로 구분한다. 선수 상세는 사진보다 이름·팀·포지션·대표 기록이 먼저 읽히며, 최근 경기와 메모는 같은 카드 언어로 스캔할 수 있어야 한다.

### 15–16 운영/정보 상세

API 진단은 사용자용 설정과 분리된 운영 화면이지만, 상태 이름·소요 시간·재시도 행동은 동일한 surface 토큰을 사용한다. 업데이트 소식은 현재 버전을 상단에 고정하고 사용자에게 보이는 변화만 짧은 bullet로 보여준다.
업데이트 소식 화면과 앱 시작 prompt는 헤더·버전·변경점 그룹을 각각 하나의 접근성 단위로 노출한다. prompt처럼 비동기 다이얼로그로 열리는 화면은 전환 완료 후에도 같은 요약이 탐색되는지 회귀로 확인한다.
