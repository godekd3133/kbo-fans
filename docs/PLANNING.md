## 1. 서비스 개요

### 한 줄 정의
**내 팀 경기를 가장 빠르게 보고, 경기 맥락까지 바로 이해하는 KBO 전용 모바일 앱**

### 비전
"야구장 밖에서도 경기장 안에 있는 것처럼" — 실시간 스코어, 투구별 문자중계, 상세 기록을 한 손에.

### 타겟 사용자

| 페르소나 | 특징 | 핵심 니즈 |
|----------|------|-----------|
| **코어팬** (30%) | 매일 경기 체크, 선수 기록까지 꼼꼼히 확인 | 문자중계, 박스스코어, 선수 기록 |
| **라이트팬** (70%) | 우리 팀 결과만 빠르게 확인 | 스코어보드, 마이팀 알림 |

### 데일리 사용 루프

KBO Fans의 핵심 반복 사용 이유는 “오늘 내 팀이 어떻게 되고 있는지”를 시간대별로 빠르게 확인하는 것이다.

| 시간대 | 사용자 질문 | 앱이 먼저 답해야 하는 것 |
|--------|-------------|--------------------------|
| 오전/점심 | 오늘 우리 팀 경기 있어? | 경기 여부, 상대, 시간, 구장, 선발 예정 |
| 경기 1~2시간 전 | 선발/라인업 떴어? 예매나 알림 필요해? | 선발 투수, 라인업 상태, 경기 시작 알림, 예매 링크 |
| 경기 중 | 지금 몇 대 몇이야? 무슨 상황이야? | 마이팀 스코어, 이닝, 주자/아웃/카운트, 최근 주요 플레이 |
| 경기 직후 | 이겼어? 누가 잘했어? | 최종 스코어, 승패 요약, 핵심 선수, 박스스코어 요약 |
| 다음 날 | 어제 결과가 순위/기록에 영향 줬어? | 순위 변동, 마이팀 최근 흐름, 주요 기록 변화 |

### 정보 깊이 원칙

| 사용자 | 1차 화면 | 2차 화면 | 3차 화면 |
|--------|----------|----------|----------|
| 라이트팬 | 홈 브리프, 스코어 카드, 알림 | 경기 상세 요약 | 순위/일정 |
| 코어팬 | 경기 상세 스코어/문자중계 | 박스스코어/라인업 | 기록실/선수 상세 |
| 예매 사용자 | 홈/일정 예매 배지 | 일정 상세 | 알림 설정 |
| 데이터형 팬 | 순위/기록실 요약 | 팀 기록/선수 상세 | 시즌 추이 |

설계 원칙은 홈에는 판단에 필요한 요약만 두고, 경기 상세에는 현재 경기 맥락, 기록실에는 시즌/선수 판단, 설정에는 개인화 제어를 둔다.

| **광고 최소화** | 네이버/야구보구 광고 과다 | MVP에서는 광고 없음, 추후 비침투적 광고만 도입 |

## 3. 화면 구성 (Information Architecture)

```
[앱 실행]
  │
  ├── 🏠 홈 (마이팀 브리프 + 오늘의 스코어보드)
  │     ├── 마이팀 브리프 (경기 상태, 상대, 주요 CTA)
  │     ├── 경기 카드 (팀 로고, 스코어, 이닝, 경기 상태)
  │     └── 탭: 경기 카드 → 경기 상세로 이동
  │
  ├── ⚾ 경기 상세
  │     ├── 탭 1: 스코어보드 (이닝별 점수 테이블)
  │     ├── 탭 2: 문자중계 (투구별 실시간 피드)
  │     ├── 탭 3: 박스스코어 (타자/투수 기록)
  │     └── 탭 4: 라인업
  │
  ├── 📅 일정
  │     ├── 캘린더 뷰 (월간)
  │     └── 날짜 선택 → 해당일 경기 목록
  │
  ├── 📊 순위
  │     └── 정규시즌 순위 테이블 (승/패/무/승률/게임차)
  │
  ├── 기록실
  │     ├── 마이팀 선수 현황
  │     └── 리그 리더 / 선수 상세
  │
  └── ⚙️ 설정
        ├── 마이팀 선택
        ├── 알림 설정 (이벤트별 on/off)
        └── 앱 정보
```

## 4. 핵심 UX 원칙

### 4.1 "열면 바로 야구"
- 앱 실행 시 **로딩 없이** 오늘의 스코어보드가 즉시 보여야 함
- 캐시된 마지막 데이터를 먼저 보여주고, 백그라운드에서 최신 데이터 fetch
- 경기 중이면 자동으로 실시간 업데이트

### 4.2 마이팀 중심
- 첫 실행 시 **응원팀 선택** (온보딩)
- 마이팀 경기 → 홈 최상단 브리프 / 카드 크기 확대
- 마이팀 관련 알림 기본 ON
- 마이팀 미선택 상태에서는 단순 빈 상태가 아니라 선택 후 달라지는 점을 설명

### 4.3 깔끔한 정보 밀도
- 스코어보드: 한 경기 = 한 카드, 한 화면에 3~4경기 표시
- 문자중계: 중요한 이벤트(득점, 삼진, 교체 등) 시각적 강조
- 박스스코어: 가로 스크롤 없이 핵심 스탯만 표시

### 4.4 팀 컬러 활용
- 각 팀의 공식 컬러를 경기 카드, 상세 화면에 적용
- 마이팀 선택 시 앱 전체 테마에 팀 컬러 반영 (선택적)

### 4.5 상태 중심 디자인
- 라이브, 경기 전, 종료, 취소/지연, 마이팀 상태를 색상과 배지로 일관되게 구분
- 라이브 레드는 경기 진행/득점성 이벤트에 제한적으로 사용
- 팀 컬러는 화면 전체 배경보다 카드 좌측 바, 선택 상태, CTA, 필터 underline 등 식별 포인트로 사용

## 6. 데이터 아키텍처

### 데이터 흐름

현재 데이터 아키텍처는 backend-backed mode와 direct KBO mode를 명시적으로 구분한다. Backend는 API-backed data, snapshot generation, push, Live Activity / Dynamic Island sync를 담당하는 active component다. Direct KBO mode는 local/offline/web preview와 resilience 검증을 위한 지원 경로로 유지한다.

```
KBO 홈페이지 (koreabaseball.com)
        │
        │  FastAPI crawler/service/snapshot
        ▼
   [FastAPI backend + scheduler]
        │
        │  API response / push / liveactivity update
        ▼
   [Flutter App Provider]
        │
        │  SharedPreferences / device cache / bundled asset
        ▼
   [화면 렌더링]
```

direct mode는 앱 단독 검증과 preview 안정성을 위해 남긴다.

```
KBO source
   │
   ▼
[Flutter direct KBO repository]
   │
   ▼
[화면 렌더링 / local resilience check]
```

### 데이터 수집 전략 (Adaptive Polling)

| 상태 | 폴링 주기 | 설명 |
|------|-----------|------|
| 경기 전 (Scheduled) | 5분 | 라인업 변경 감지 용 |
| 경기 중 (Live) | 8초 | 실시간 스코어/중계 |
| 경기 종료 (Final) | 안 함 | 최종 데이터 1회 저장 |
| 비시즌/휴식일 | 안 함 | 크롤링 중단 |

### 푸시 / 앱 밖 Moment

알림은 강도 조절이 아니라 `Moment Subscription` 으로 설계한다. 사용자는 어떤 야구 장면을 받을지, 그 장면을 push / summary / Live surface / off 중 어디로 보낼지 고른다.

| Moment | 트리거 조건 | 기본 전달 방식 | 표면 |
|--------|-------------|----------------|------|
| 경기 시작 | 경기 상태 → Live 전환 | 바로 알림 | Push |
| 라인업 공개 | 선발/라인업 데이터 최초 공개 | 요약 | Notification Summary / 앱 내 카드 |
| 득점권 | 주자 득점권 + 타석 진행 | Live 표면만 | Live Activity / Android Live Update |
| 득점/실점 | 마이팀 경기 스코어 변경 | 바로 알림 | Push |
| 동점/역전 | 승패 상태 변경 | 바로 알림 | Push |
| 투수 교체 | 문자중계/라인업 기준 투수 변경 | 요약 | Notification Summary |
| 내 선수 타석 | 관심 선수 타석 진입 | Live 표면만 | Phase 1.5 개인화 |
| 최종 결과 | 경기 상태 → Final 전환 | 바로 알림 | Push + Live surface 종료 |

**앱 밖 표면 원칙**:
- 첫 실행에서 push permission 을 요청하지 않는다.
- `경기 따라가기` 또는 특정 Moment 알림을 사용자가 직접 선택한 뒤 예시 sheet 를 보여주고 권한을 요청한다.
- Live Activity / Android Live Update 는 사용자가 시작한 follow session 에서만 켠다.
- Widget 은 실시간 중계가 아니라 마이팀 상태판이며 stale/update time 을 반드시 보여준다.

## 7. 기술 스택 (안)

| 레이어 | 기술 | 이유 |
|--------|------|------|
| **모바일 앱** | Flutter (Dart) | iOS/Android 동시 지원, 수업 필수 요구사항 |
| **상태 관리** | Riverpod | 컴파일 타임 안전성, 비동기 상태(AsyncValue) 기본 지원 |
| **네비게이션** | go_router | 선언적 라우팅, 딥링크 지원 |
| **HTTP** | dio | 인터셉터, 캐시, 에러 핸들링 편리 |
| **백엔드 API** | Python FastAPI | API-backed data, snapshot generation, push, Live Activity / Dynamic Island sync의 active runtime component |
| **크롤링** | requests + BeautifulSoup | SSR 페이지에 충분, 가볍고 빠름 |
| **DB** | AWS RDS (PostgreSQL) | 운영 backend를 확장할 때의 정형 데이터 후보 |
| **캐시** | AWS ElastiCache (Redis) | 운영 backend를 확장할 때의 실시간 캐시 후보 |
| **푸시** | Firebase Cloud Messaging (FCM) | iOS/Android 통합 푸시 |
| **배포** | AWS ECS/Fargate | 앱 종료 후 push / Live Activity 시연 backend 배포 후보 |
