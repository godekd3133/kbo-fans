## 1. 서비스 개요

### 한 줄 정의
**KBO 프로야구 팬을 위한 실시간 경기 정보 모바일 앱**

### 비전
"야구장 밖에서도 경기장 안에 있는 것처럼" — 실시간 스코어, 투구별 문자중계, 상세 기록을 한 손에.

### 타겟 사용자

| 페르소나 | 특징 | 핵심 니즈 |
|----------|------|-----------|
| **코어팬** (30%) | 매일 경기 체크, 선수 기록까지 꼼꼼히 확인 | 문자중계, 박스스코어, 선수 기록 |
| **라이트팬** (70%) | 우리 팀 결과만 빠르게 확인 | 스코어보드, 마이팀 알림 |

### 경쟁 앱 상세 분석

| 앱 | 운영사 | 주요 기능 | 장점 | 단점 | 사용자 주요 불만 |
|----|--------|-----------|------|------|-----------------|
| 네이버 스포츠 | 네이버 | 실시간 스코어, 하이라이트, 뉴스, 커뮤니티 | 국내 최대 DAU, 뉴스+스코어+커뮤니티 원스톱, 네이버 ID 연동 | 야구 전용 아님, 광고 과다, 앱 무거움, 팀별 알림 세분화 불가 | 스코어 3~5초 지연, 알림 커스터마이징 부족 |
| SPORTS.i (KBO 공식) | KBO | 공식 스코어, 선수 전체 기록, 투구 궤적/구종 분석 | 가장 정확한 통계, 심판 판정 데이터, 타자-투수 매치업 | UI 구식, 로딩 느림, 잦은 크래시, iOS 대응 느림 | "2015년 디자인", "자꾸 튕김", "로그인 풀림" |
| 야구보구 | 개인 개발 | 실시간 문자중계, 투구 카운트, 즐겨찾기 | 야구 특화 UX, 가볍고 빠름, 문자중계 품질 좋음 | iOS 지원 미흡, 광고 多, 유지보수 불안정 | "광고 너무 많음", "iOS 기능 부족", "업데이트 불규칙" |
| ESPN | ESPN Inc. | KBO 스코어, MLB+KBO 통합 | 글로벌 수준 앱 품질, 멀티리그 동시 팔로우 | KBO 5~10분 지연, 한국어 미지원, 세부 통계 부족 | "KBO 중계 거의 없음", "선수 이름 로마자만" |

### 사용자 불만 공통 패턴 (전 앱 공통)

| 불만 유형 | 빈도 | 설명 |
|-----------|------|------|
| 실시간 스코어 지연 | 매우 높음 | 모든 앱이 3~10초 지연 |
| 광고 과다 | 높음 | 네이버, 야구보구 |
| 앱 크래시/불안정 | 높음 | SPORTS.i, KBO 공식 |
| 알림 커스터마이징 부족 | 중간 | 선수별/이닝별 세밀한 알림 없음 |
| 레거시 UI/UX | 높음 | SPORTS.i, KBO 공식 |

### 시장 기회 (현재 공백 영역)

| 기회 | 현재 상황 |
|------|-----------|
| 야구 전용 + 모던 UX | SPORTS.i는 구식, 네이버는 종합 스포츠 |
| 세밀한 개인화 알림 | 선수별/이벤트별 알림 제공하는 앱 없음 |
| iOS/Android 동일 품질 | 야구보구 등 iOS 지원 미흡 |
| 광고 없는 깔끔한 경험 | 대부분 광고 과다 |

### 차별화 전략 (KBO Fans)

| 전략 | 경쟁사 대비 차별점 | UX 적용 |
|------|-------------------|---------|
| **야구 전용 모던 UX** | 네이버(종합), SPORTS.i(구식) 대비 야구에만 집중한 깔끔한 UI | 앱 열면 0.5초 내 오늘 스코어보드 표시, 불필요한 메뉴 제거 |
| **마이팀 중심 경험** | 타 앱은 전 경기 동등 나열 | 마이팀 경기 상단 고정 + 확대 카드, 팀 컬러 테마, 온보딩에서 팀 선택 |
| **세밀한 푸시 알림** | 타 앱은 "경기 결과" 수준의 단순 알림 | 득점/홈런/역전/삼진 등 이벤트별 on/off, 마이팀 vs 전체 경기 선택 |
| **빠른 문자중계** | 야구보구 수준의 문자중계 + 볼카운트 시각화 | 투구별 실시간 피드, 득점 이벤트 시각적 강조, 이닝 점프 |
| **iOS/Android 동일 경험** | 야구보구 iOS 미흡 | Flutter로 양 플랫폼 동일 품질 보장 |
| **광고 최소화** | 네이버/야구보구 광고 과다 | MVP에서는 광고 없음, 추후 비침투적 광고만 도입 |

| **경기 상세 — 문자중계** | 투구별 실시간 텍스트 중계 + 볼카운트 | P0 |

| **마이팀 설정** | 응원 팀 선택 → 스코어보드/알림에서 우선 표시 | P1 |

## 3. 화면 구성 (Information Architecture)

```
[앱 실행]
  │
  ├── 🏠 홈 (오늘의 스코어보드)
  │     ├── 경기 카드 (팀 로고, 스코어, 이닝, 경기 상태)
  │     ├── 마이팀 경기 → 상단 고정
  │     └── 탭: 경기 카드 → 경기 상세로 이동
  │
  ├── ⚾ 경기 상세
  │     ├── 탭 1: 스코어보드 (이닝별 점수 테이블)
  │     ├── 탭 2: 문자중계 (투구별 실시간 피드)
  │     ├── 탭 3: 박스스코어 (타자/투수 기록)
  │     └── 탭 4: 라인업
  │
  ├── 📅 일정
  │     ├── 캘린더 뷰 (월간)
  │     └── 날짜 선택 → 해당일 경기 목록
  │
  ├── 📊 순위
  │     └── 정규시즌 순위 테이블 (승/패/무/승률/게임차)
  │
  └── ⚙️ 설정
        ├── 마이팀 선택
        ├── 알림 설정 (이벤트별 on/off)
        └── 앱 정보
```

### 하단 네비게이션 (Bottom Tab)

| 탭 | 아이콘 | 화면 |
|----|--------|------|
| 홈 | ⚾ | 오늘의 스코어보드 |
| 일정 | 📅 | 경기 일정 |
| 순위 | 📊 | 팀 순위 |
| 설정 | ⚙️ | 마이팀/알림 설정 |

## 4. 핵심 UX 원칙

### 4.1 "열면 바로 야구"
- 앱 실행 시 **로딩 없이** 오늘의 스코어보드가 즉시 보여야 함
- 캐시된 마지막 데이터를 먼저 보여주고, 백그라운드에서 최신 데이터 fetch
- 경기 중이면 자동으로 실시간 업데이트

### 4.2 마이팀 중심
- 첫 실행 시 **응원팀 선택** (온보딩)
- 마이팀 경기 → 스코어보드 최상단 / 카드 크기 확대
- 마이팀 관련 알림 기본 ON

### 4.3 깔끔한 정보 밀도
- 스코어보드: 한 경기 = 한 카드, 한 화면에 3~4경기 표시
- 문자중계: 중요한 이벤트(득점, 삼진, 교체 등) 시각적 강조
- 박스스코어: 가로 스크롤 없이 핵심 스탯만 표시

### 4.4 팀 컬러 활용
- 각 팀의 공식 컬러를 경기 카드, 상세 화면에 적용
- 마이팀 선택 시 앱 전체 테마에 팀 컬러 반영 (선택적)

## 6. 데이터 아키텍처

### 데이터 흐름

```
KBO 홈페이지 (koreabaseball.com)
        │
        │  크롤링 (requests + BeautifulSoup / POST API)
        ▼
   [Backend Server]
        │
        │  REST API (JSON)
        ▼
   [Mobile App]
        │
        │  로컬 캐시 (AsyncStorage/SQLite)
        ▼
   [화면 렌더링]
```

### 데이터 수집 전략 (Adaptive Polling)

| 상태 | 폴링 주기 | 설명 |
|------|-----------|------|
| 경기 전 (Scheduled) | 5분 | 라인업 변경 감지 용 |
| 경기 중 (Live) | 30초~1분 | 실시간 스코어/중계 |
| 경기 종료 (Final) | 안 함 | 최종 데이터 1회 저장 |
| 비시즌/휴식일 | 안 함 | 크롤링 중단 |

### 푸시 알림 이벤트

| 이벤트 | 트리거 조건 | 기본값 |
|--------|-------------|--------|
| 경기 시작 | 경기 상태 → Live 전환 | ON (마이팀만) |
| 득점 | 스코어 변경 감지 | ON (마이팀만) |
| 홈런 | 문자중계에서 "홈런" 키워드 | ON (마이팀만) |
| 경기 종료 | 경기 상태 → Final 전환 | ON (마이팀만) |
| 역전 | 스코어 역전 감지 | ON (마이팀만) |

## 7. 기술 스택 (안)

| 레이어 | 기술 | 이유 |
|--------|------|------|
| **모바일 앱** | Flutter (Dart) | iOS/Android 동시 지원, 수업 필수 요구사항 |
| **상태 관리** | Riverpod | 컴파일 타임 안전성, 비동기 상태(AsyncValue) 기본 지원 |
| **네비게이션** | go_router | 선언적 라우팅, 딥링크 지원 |
| **HTTP** | dio | 인터셉터, 캐시, 에러 핸들링 편리 |
| **백엔드 API** | Python FastAPI | 크롤링(Python) + API 서빙 한 곳에서 |
| **크롤링** | requests + BeautifulSoup | SSR 페이지에 충분, 가볍고 빠름 |
| **DB** | AWS RDS (PostgreSQL) | 정형 데이터에 적합, 관리형 서비스 |
| **캐시** | AWS ElastiCache (Redis) | 실시간 스코어 캐시, pub/sub |
| **푸시** | Firebase Cloud Messaging (FCM) | iOS/Android 통합 푸시 |
| **배포** | AWS (EC2 또는 ECS) | 백엔드 서버 배포 |

## 8. MVP 마일스톤
