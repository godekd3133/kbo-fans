## 디자인 시스템

### 기본 설정

- **프레임**: 390×844px (iPhone 14 기준, 모바일 앱)
- **스타일**: 모던, 미니멀, 다크 모드 기반 스포츠 앱
- **폰트**: Jua (한글/영문/숫자). Flutter 앱은 `Jua-Regular.ttf`를 전역 기준으로 번들에 포함하고, `NanumSquareRoundL/R/B/EB.ttf`와 Pretendard는 fallback으로 유지한다.
- **라운드**: Hero 카드 12px, 일반/요약 카드 8px, 버튼 12px, 입력 8px
- **아이콘**: 앱 UI에서는 이모지 텍스트를 쓰지 않고, 홈/일정/기록/데이터 브리핑/설정 의미의 벡터 아이콘을 사용
- **앱 구현 기준**: 2026-07-23 전면 페르소나 감사 이후 실제 Flutter 화면은 430px 이하 mobile frame, 700px rail 전환, 최대 720px tablet content, 8px 카드, 작은 outline bottom tab, 상태 우선 헤더를 기본값으로 둔다.
- **보조 비주얼 리소스**: 리얼/시네마틱 사진풍이 아니라 캐주얼 2.5D 스티커형 야구 일러스트를 사용한다. 화면별 25개 단위 리소스는 48~54px 높이의 가로 레일로 다루고, 로고/읽을 수 있는 텍스트/실제 선수 얼굴을 넣지 않는다.

### Bottom Tab Bar (공통)

- 5탭: 홈 | 일정 | 기록 | 브리핑 | 설정
- 높이: 83px (하단 Safe Area 34px 포함)
- 배경: #0F0F0F, 상단 구분선 #333333 (0.5px)
- 활성 탭: #FFFFFF 아이콘 + 텍스트
- 비활성 탭: 읽을 수 있는 secondary 색 아이콘 + 텍스트
- 아이콘 24px, 텍스트 10px, 간격 4px
- 각 탭의 실제 조작 영역은 최소 48px 높이, 일반 pressable은 최소 44×44px로 제작
- 가운데 탭을 반드시 홈으로 고정하지 않아도 된다. 5탭에서는 홈을 첫 번째 또는 중앙 중 구현 기준에 맞추되, 현재 앱 구조와 동일하게 유지한다.
- 모바일에서 `/standings`와 `/records` 하위 화면은 모두 `기록` 탭을 선택 상태로 표시한다.

### Tablet / Foldable Navigation

- 700px 이상: Bottom Tab을 제거하고 왼쪽에 `홈 / 일정 / 순위 / 기록 / 브리핑 / 설정` 6개 목적지 `NavigationRail` 배치
- 1000px 이상: 같은 rail을 200px 안팎의 extended label 형태로 확장
- 콘텐츠는 rail을 제외한 영역 중앙에 최대 720px로 배치한다. 430px 모바일 column을 그대로 두거나 전체 너비로 과도하게 늘리지 않는다.
- Figma에 700×844 compact rail, 1024×768 extended rail의 홈·순위 대표 frame을 함께 만든다.

### Page 0: User Flow

화면 간 네비게이션 흐름을 다이어그램으로 만들어주세요.

```text
[앱 실행]
   │
   ├─ 최초 실행 ──▶ [1. 온보딩: 마이팀 선택]
   │                        │
   │                  팀 선택 or 건너뛰기
   │                        │
   │                        ▼
   └─ 재실행 ─────▶ [2. 홈: 마이팀 브리프 + 스코어보드] ◀── Bottom Tab "홈"
                         │
                    경기 카드 탭
                         │
                         ▼
                    [3. 경기 상세] ←── 뒤로
                         ├── 탭: 스코어 (이닝별 점수)
                         ├── 탭: 문자중계 (투구별 실시간)
                         ├── 탭: 박스스코어 (타자/투수 기록)
                         └── 탭: 라인업 (선발 라인업)

                    [4. 일정] ◀── Bottom Tab "일정"
                         │
                    날짜 선택 → 경기 목록 → [3. 경기 상세]

                    [5. 순위] ◀── 홈/브리핑/기록 영역
                         (모바일 Bottom Tab "기록" 선택 / 700px+ Rail "순위")

                    [6. 기록실] ◀── Bottom Tab "기록" / 700px+ Rail "기록"
                         ├── 마이팀 선수 현황
                         ├── 리그 리더
                         └── 선수 카드 탭 → [선수 상세]

                    [7. 설정] ◀── Bottom Tab "설정"
                         ├── 마이팀 선택 / 변경
                         ├── 알림함
                         └── 세부 설정 및 지원
```

- 각 화면을 라운드 사각형(#1A1A1A, border #333333)으로 표현
- 화살표로 연결, 조건은 화살표 위에 텍스트 표기
- 모바일 Bottom Tab 5개를 하단에 수평으로 배치하고, `기록`에서 순위와 기록실 두 화면으로 연결한다. 700px+ variant는 6개 rail 목적지를 별도로 표시한다.
- 배경 #0F0F0F, 텍스트 #FFFFFF

### Page 1: 온보딩 - 마이팀 선택

최초 실행 시 응원 팀을 선택하는 온보딩 화면. **Bottom Tab 없음.**

**레이아웃 (위에서 아래)**:

1. **상단 여백**: 80px (Status Bar + 추가 여백)
2. **앱 로고**: "KBO Fans" — 중앙정렬, Jua 28px, #FFFFFF
3. **서브 텍스트**: "응원하는 팀을 선택하세요" — 중앙정렬, 16px, #B0B0B0, 상단 마진 8px
4. **개인화 설명**: 상단 마진 16px, 좌우 패딩 32px, 12px #B0B0B0
   - "홈에서 내 팀 경기 먼저 보기"
   - "원하는 경기 알림은 나중에 선택하기"
   - "일정과 기록을 내 팀 중심으로 보기"
5. **팀 선택 그리드**: 상단 마진 28px
   - 2열 5행 그리드, 가로 간격 24px, 세로 간격 20px
   - 각 팀 셀: 원형 로고 이미지(64×64px) + 팀명(12px, #B0B0B0, 마진 top 8px)
   - **미선택 상태**: 로고에 3px border #333333
   - **선택 상태**: 로고에 3px border 팀 Primary 컬러 + 우하단 체크 아이콘(20px, 흰색 배경 원형 + 팀 컬러 체크)
   - 한 번에 1팀만 선택 가능 (탭하면 이전 선택 해제)
   - 팀 배치 순서 (좌→우, 위→아래): LG, KT, SSG, 삼성, NC, 한화, 롯데, KIA, 두산, 키움
6. **시작하기 버튼**: 상단 마진 32px
   - 전체 너비 (좌우 패딩 24px), 높이 52px, 라운드 12px
   - **미선택**: 배경 #333333, 텍스트 #666666, 비활성
   - **선택**: 배경 선택된 팀 Primary 컬러, 텍스트 #FFFFFF
   - 텍스트: "시작하기" Jua 16px
7. **건너뛰기**: 상단 마진 16px, "건너뛰기" 14px, #666666, 중앙정렬, 밑줄 없음

**Figma에 2가지 상태를 프레임으로 만들어주세요**: "미선택 상태" / "LG 선택 상태"

- `시작하기`는 로컬 팀 저장이 끝나면 즉시 홈으로 이동한다. 네트워크 push 등록 대기나 실패를 이 버튼의 loading/error 상태로 표현하지 않는다.
- 온보딩과 다음 앱 startup에서 OS 알림 permission sheet를 자동으로 띄우지 않는다. 권한 preview와 OS sheet는 설정의 알림 허용 또는 경기 상세의 `경기 팔로우하기` CTA 이후에만 그린다.

### Page 11: 앱 밖 경험 (Push + Live + Widget)

`docs/design/kbo-fans-mobile-ui-alerts-outside-v4-2026-05-19/index.html`의 v4 방향을 기준으로, Push / Notification Summary / Live Activity / Android Live Update / Widget 을 한 페이지에 나열한다.

#### iOS Live Activity

```text
LG 2 : 1 KT · 7회말
1사 1,3루 · B2 S1 O1
방금: 문보경 안타
```

- Lock Screen rectangular frame 와 Dynamic Island compact/expanded frame 를 함께 제작
- 마이팀 live/라인업 공개·시작 10분 전 자동 target 또는 사용자가 경기 상세에서 직접 `경기 팔로우하기`를 선택한 경기를 표시
- 스코어, 이닝, 주자, B/S/O, 마지막 변화, 마지막 업데이트 시각, "그만 보기" action 포함
- `scoreAvailable=false`이면 `0`이 아니라 `–`를 사용한다. Dynamic Island compact/expanded/minimal과 Lock Screen의 native score label도 같은 규칙을 따르고, 접근성 annotation에는 `팀명 점수 확인 중` 또는 `양 팀 점수 확인 중`을 적는다.
- 경기 종료/취소 후 최종 상태를 짧게 보여주고 종료한다. 서스펜디드는 `중단` 상태를 표시한 채 follow/session을 유지하고 재개를 기다린다.

#### Android Live Update

- Status chip + ongoing notification 변형을 함께 제작
- 상단 chip: "따라가는 중" + 현재 스코어
- 본문: 이닝/주자/B-S-O/최근 변화
- 명시적 "그만 보기" action
- 앱이 자동으로 모든 마이팀 경기를 Live Update 로 시작하는 화면을 만들지 말 것

#### Widget Strategy

위젯은 실시간 중계가 아니라 Status Board 로 디자인한다.

**Small** (소형):

- 하나의 마이팀 상태만 표시
- 상태 1: 다음 경기 — "LG 오늘 18:30 · vs KT · 잠실"
- 상태 2: 경기 중 — "LG 2 : 1 KT · 7회말 · 2분 전"
- 상태 3: 경기 없음 — "오늘 경기 없음 · 다음 5.20"
- 상태 4: 점수 미확인 — "LG – : – KT · 점수 확인 중". null을 실제 0점으로 그리지 않는다.
- 마지막 업데이트 시각 또는 stale 상태 필수

**Medium** (중형):

- 현재 마이팀 경기 + 다음 경기 또는 오늘 마이팀 + 리그 핵심 경기
- 미니 이닝 스코어 테이블을 기본으로 넣지 말 것
- Pitch-by-pitch, 문자중계, 타석별 변화는 위젯에 넣지 말 것

#### Push Stack

- Direct push: 득점/실점, 동점/역전, 최종 결과처럼 즉시성 높은 Moment
- Summary: 라인업, 투수 교체, 기록성/예매성 정보
- Live-only: 득점권, 내 선수 타석처럼 follow session 에서만 의미 있는 Moment
- Off: 사용자가 명시적으로 끈 Moment
- 경기 상세 화면을 보고 있는 중에는 같은 경기의 direct push 를 중복 표시하지 않는 상태를 별도 frame 으로 표현
