# KBO Fans 시장 비교와 리뉴얼 방향

조사 기준일: 2026-09-07. 제품 방향은 **내 팀의 지금을 바로 보고, 궁금한 기록을 이해하며 다음 경기까지 이어가는 앱**이다. 전체 작업 범위와 검증 현황은 [리뉴얼 작업 문서](RENEWAL_2026-09-07.md)를 따른다.

## 조사 방법과 확인 범위

공식 서비스 사이트, 공식 도움말, 개발자가 작성한 App Store·Google Play 설명을 확인했다. 이는 제품이 제공한다고 명시한 기능의 조사다. 경쟁 앱을 설치해 로그인하거나 화면·전달 지연·알림 성공률을 측정한 사용성 감사는 아니다.

- 표에 없는 기능은 미확인이다. 해당 제품에 기능이 없다고 단정하지 않는다.
- 공식 등록정보는 기능 제공 주체의 설명이며, 속도·정확성 우위를 독립적으로 입증하지 않는다.
- 검색 결과에 남은 이전 명칭과 현재 공식 등록정보가 다르면 현재 페이지를 기준으로 한다.
- 네이버 스포츠 본문 페이지는 이번 조사 도구에서 열리지 않았다. 공식 도움말로 확인한 MY팀·알림 범위만 비교하고, 현재 뉴스·중계 UI를 직접 점검했다고 표현하지 않는다.
- 사용자 리뷰와 별점은 시장 전체의 선호나 품질을 증명하는 자료로 사용하지 않았다.

## 차별화 가설과 검증 방법

아래는 경쟁사에 없다고 입증한 기능이 아니라, 현재 KBO Fans의 Flutter·FastAPI·공식 데이터 경로로 구현하고 검증할 수 있는 제품 가설이다.

| 가설 | 사용자가 얻는 결과 | 검증할 기준 | 데이터 조건 |
|---|---|---|---|
| **내 팀 상태를 먼저 답한다** | 홈 진입 후 진행 경기·예정 경기·종료·휴식일을 바로 구분하고 다음 행동으로 이동한다. | 홈 첫 데이터 화면에서 내 팀 상태를 찾는 시간, 경기 또는 라인업까지의 탭 수, 더블헤더 대상 정확성. | 현재 scoreboard를 먼저 사용하고 다음 경기 aggregate를 기다리느라 첫 답을 지연하지 않는다. |
| **점수에서 경기 흐름을 이해한다** | 승패·점수 차와 득점 이닝을 보고 중계·박스스코어로 이어간다. | 점수 차와 누적 이닝 점수의 일치, 누락 데이터에서 잘못된 서사가 나오지 않는지, 상세 탭 이동 성공. | 검증된 양 팀 총점과 연속된 반이닝 데이터가 일치할 때만 계산한다. |
| **궁금한 기록을 읽고 비교한다** | 기록의 뜻을 이해하고 같은 시즌의 선수 정보를 비교한다. | 시즌 보존, 기록 설명 발견 가능성, 비교 대상·지표·단위 일치, 대형 글꼴 가독성. | 화면·자식 route·provider의 시즌이 같아야 한다. 없는 지표를 0이나 예상값으로 대체하지 않는다. |
| **다시 열었을 때 놓친 변화부터 알려준다** | 마지막 확인 이후 무엇이 달라졌는지 짧게 파악하고 해당 중계 구간으로 이동한다. | 미확인 구간의 정확한 시작점, 이벤트 정정·중복 처리, 복귀 후 상황 파악 시간. | 마지막 본 경기·이벤트 식별자와 검증된 이벤트 순서가 필요하다. 이번 리뉴얼의 득점 이닝 요약과 다른 후속 기능이다. |
| **따라본 경기를 개인 기록으로 연결한다** | 관심 경기를 보관하고 직관·집관·한 줄 메모로 다시 찾는다. | 실제 저장·재방문율, 기록 작성 시간, 공식 결과와 개인 메모의 분리. | 기존 역사 스냅샷·경기 ID를 재사용하고 개인 기록 저장·복구 계약을 별도로 설계한다. |

디자인의 기준은 장식의 양이 아니라 **첫 화면의 답, 정보의 순서, 정확한 수치, 읽을 수 있는 근거, 다음 행동의 발견 가능성**이다. 일반 팬을 위해 설명을 쉽게 하면서도 코어 팬이 필요로 하는 이닝·선수·시즌 정보를 숨기지 않는다.

## 이번 리뉴얼에서 소스에 반영한 범위

아래의 “소스 반영”은 현재 작업 트리에서 구현을 확인했다는 뜻이다. 전체 제품 검증·배포·경쟁 앱 대비 우위 입증을 의미하지 않는다. 최종 테스트·실제 화면 증거는 전체 리뉴얼 작업 문서에 기록한다.

| 사용자 경험 | 소스 반영 내용 | 현재 증거·한계 |
|---|---|---|
| 온보딩 | `응원팀을 고르면 경기에서 기록까지` 가치 설명, 선택 팀과 오늘 경기·다음 일정·팀 기록의 짧은 미리보기, 팀색 선택 표시·CTA. | 온보딩 위젯 테스트 11개 통과. 저장·편집 복귀·접근성 계약을 검증했다. |
| 내 팀 홈 | 현재 scoreboard 기반 포커스 카드, 진행 중 경기 우선, 예정·종료·취소·중단 상태별 행동, 휴식일의 다음 경기 안내. | 현재 구현 경로를 읽어 확인. lineupOpened CTA는 `tab=lineup`으로 연결하도록 독립 리뷰 후 수정했다. 전체 실화면 검증은 별도다. |
| 경기 이해 | `경기 한눈에`에서 검증된 점수 차, 반이닝 순서의 득점·누적 점수, 중계·선수 기록·라인업 연결. | 중간 누락·음수·총점 불일치 시 서사를 생성하지 않는 소스와 관련 회귀 테스트를 확인했다. 마지막 방문 이후의 변화 요약은 아직 아니다. |
| 핵심 중계 탐색 | `핵심 장면` 필터에서 기존 중계 이벤트의 득점·홈런·교체·경기 종료를 모은다. | 기존 이벤트 데이터의 필터링이다. 영상 생성·AI 해설·승리 기여도·새 예측 모델은 포함하지 않는다. |
| 기록 탐색 | 기록 설명·선수 비교 동선, 기록 화면의 명시적 시즌과 자식 route 연결. | 현재 관련 소스 변경을 확인했다. 정확한 기능별 회귀 결과는 담당 검증 기록을 따른다. |
| 데이터 브리핑 | 필터 우선 배치, 경기·순위·기록 우선 리드, 예매 시각의 KST/예상·공식 구분, 각 사실의 1회 표시, 데이터 근거와 생성 날짜·한국시간, 좁은 폭·큰 글꼴 재배치. | 브리핑 위젯 테스트 19개 통과. 기사 제공 기능이 아니며 외부 뉴스 출처를 가장하지 않는다. |
| 공통 디자인 | 행동·탐색에 accent 색상, 일정 의미에 맞는 아이콘, 선택 목적지 표시, 바텀시트 모양 정리. | 전역 theme·navigation의 현재 diff를 확인했다. 실기기와 OS별 렌더링은 별도 증거가 필요하다. |

온보딩과 브리핑에 수행한 검증은 해당 소유 파일의 Dart 분석과 위젯 테스트다. 이 결과를 전체 Flutter 앱·백엔드·실기기 푸시·TestFlight 승인 결과로 확대하지 않는다.

## 향후 실험으로 남긴 범위

1. **미확인 변화 요약**: 마지막으로 본 이벤트를 저장하고 복귀 시 이후의 변화를 보여준다. 현재 득점 이닝 흐름이나 핵심 장면 필터가 이 기능을 대신한다고 홍보하지 않는다.
2. **순위 맥락 연결 강화**: 내 팀과 다음 상대의 검증된 순위·게임차·시리즈 일정을 연결한다. 검증되지 않은 진출 확률·예상 승률을 덧붙이지 않는다.
3. **관심 경기·직관·집관 기록**: 개인 보관 수요부터 확인한다. 사진 서버·친구·공개 피드·현장 커뮤니티 확장은 운영 비용과 사용 수요를 확인한 뒤 결정한다.
4. **스포일러 제어와 알림 세분화**: 필요성이 확인되면 앱 화면·알림·위젯·Live Activity 전부의 일관된 정책을 설계한다. 화면 하나에서 점수를 가리는 것으로 완료 처리하지 않는다.
5. **같은 경기의 경쟁 앱 비교 실험**: 동일 기기·네트워크·경기에서 초기 표시 시간, 상태 확인 탭 수, 데이터 변경 지연, 대형 글꼴 가독성을 측정한다. 이 실험 전에는 시장에서 가장 빠르거나 정확하다고 주장하지 않는다.

출시 후 우위는 기능 목록의 길이가 아니라 사용자가 내 팀의 상황을 얼마나 빨리 정확하게 이해하고 다시 찾는지로 평가한다.
