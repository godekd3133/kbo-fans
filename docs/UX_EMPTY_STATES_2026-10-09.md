# 빈 결과와 중계 필터 개선

## 사용자 문제와 목표

완료된 응답인데도 기록과 라인업이 ‘준비 중’으로 표시되어 기다리면 생길 정보처럼 보였다. 중계 필터는 선택한 이닝과 무관한 건수를 보여주고 결과 없는 종류까지 나열했다. 빈 결과, 실제 로딩, API 실패를 구분하며 다음 탐색을 방해하는 장식과 빈 항목을 줄인다.

## 영향 범위

- 앱: 기록실, 홈 기록 문구, 라인업 빈 상태, 중계 필터. 원자료·시즌·API routing·cache 검증은 유지한다.
- 백엔드: records overview producer의 ranked payload 검증과 앱 consumer를 확인했다. 운영 서버·scheduler·snapshot 정책 변경 없음.
- QA: reference API에 `--include-snapshots --omit-record-metric saves`를 명시하면 선택한 추가 지표만 메모리에서 비운다. 핵심 순위·원본 파일·시즌·생성 시각은 유지한다. 운영 최신성의 증거가 아니다.
- 인프라·릴리스·푸시: 변경 없음.

## 구현

- 완료된 빈 기록은 ‘이 시즌의 해당 기록이 없어요.’로 표시한다. 비어 있는 추천 카드, 표 열 제목, 해당 지표의 전체 보기 버튼을 숨긴다. 지표 전환과 정상 결과의 전체 보기는 유지한다.
- 라인업/불펜/문자중계 빈 응답은 현재 제공된 정보가 없다는 문구로 표시한다. 실제 로딩과 실패 분기는 유지한다.
- 중계 종류의 건수는 선택 이닝 내에서 계산한다. 결과 없는 비활성 종류는 숨기고 선택된 종류와 전체 필터는 유지해 필터에서 빠져나올 수 있다.
- 홈에서 값이 없는 완료된 기록을 집계 진행처럼 표현하지 않는다.

## 계약 검증

2002 snapshot은 모든 핵심 순위가 비어 있었다. reference API가 원본을 HTTP 200으로 내보내도 앱은 기존 rank-1 검증으로 오류 처리한다. 이를 정상 빈 결과로 간주해 검증을 느슨하게 바꾸지 않았다. 합법적인 부분 빈 결과는 avg/hr/ops/era가 rank 1부터 있고 saves만 빈 응답으로 확인한다. 테스트도 같은 구조로 수정했다.
