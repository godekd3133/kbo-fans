# KBO Fans 기획/디자인 보강 제안

> 작성일: 2026-05-18  
> 범위: 현재 `CLAUDE.md`, `docs/PLANNING.md`, `docs/APP_SPEC.md`, `docs/FIGMA_PROMPT.md`, `docs/UX_AUDIT_2026-03-31.md`, `docs/WORKLOG.md` 기준 제품 기획과 UI/UX 보강점 정리  
> 상태: Product/Design Audit v1

---

## 1. 현재 판단

KBO Fans의 현재 기획은 “KBO 실시간 경기 정보 앱”으로서 MVP 골격은 충분히 잡혀 있다. 홈 스코어보드, 경기 상세, 일정, 순위, 기록실, 설정, 알림, 위젯까지 주요 면은 이미 정의되어 있고, 기술적으로도 Flutter/FastAPI/KBO direct fallback/snapshot-first 전략이 구체화되어 있다.

다만 제품 관점에서는 아직 세 가지가 더 선명해져야 한다.

1. **왜 매일 이 앱을 켜야 하는가**
   - 현재는 기능 목록은 많지만, 매일 반복 진입을 만드는 “마이팀 데일리 루프”가 아직 약하다.
2. **라이트팬과 코어팬을 어떻게 동시에 만족시키는가**
   - 홈은 빠르게, 상세/기록실은 깊게 가야 하는데 화면별 정보 깊이 기준이 더 필요하다.
3. **KBO Fans만의 시각적 정체성이 무엇인가**
   - 다크 스포츠 앱 방향은 맞지만, 팀 컬러/라이브 상태/선수 이미지/경기 흐름을 엮은 고유한 디자인 언어가 더 필요하다.

## 2. 제품 기획 보강 방향

### 2.1 핵심 제품 문장 재정의

현재 한 줄 정의는 “KBO 프로야구 팬을 위한 실시간 경기 정보 모바일 앱”이다. 기능 설명으로는 맞지만 차별점은 약하다.

권장 제품 문장:

> **내 팀 경기를 가장 빠르게 보고, 경기 맥락까지 바로 이해하는 KBO 전용 모바일 앱**

이 문장이 더 나은 이유:

- “내 팀”이 개인화 방향을 고정한다.
- “가장 빠르게”가 홈/캐시/경량 로딩 전략과 연결된다.
- “경기 맥락”이 문자중계, 박스스코어, 라인업, 기록실을 하나로 묶는다.
- “KBO 전용”이 네이버 스포츠와의 차이를 명확히 한다.

### 2.2 데일리 사용 루프 추가

현재 기능은 화면 단위로 잘 정리되어 있지만, 사용자가 하루에 몇 번 들어오는지에 대한 루프가 약하다. 아래 루프를 제품 원칙으로 추가하는 것이 좋다.

| 시간대 | 사용자 질문 | 앱이 먼저 보여줘야 하는 것 |
| --- | --- | --- |
| 오전/점심 | 오늘 우리 팀 경기 있어? | 오늘 경기 여부, 상대, 시간, 구장, 선발 예정 |
| 경기 1~2시간 전 | 선발/라인업 떴어? 예매나 알림 필요해? | 선발 투수, 라인업 상태, 경기 시작 알림, 예매 링크 |
| 경기 중 | 지금 몇 대 몇이야? 무슨 상황이야? | 마이팀 스코어, 이닝, 주자/아웃/카운트, 최근 주요 플레이 |
| 경기 직후 | 이겼어? 누가 잘했어? | 최종 스코어, 승패 요약, MVP급 선수, 박스스코어 핵심 |
| 다음 날 | 어제 결과가 순위/기록에 영향 줬어? | 순위 변동, 마이팀 최근 흐름, 주요 기록 변화 |

이 루프를 기준으로 홈 화면과 푸시 알림, 위젯, 기록실 우선순위를 다시 정렬해야 한다.

### 2.3 마이팀 브리프를 제품 중심으로 승격

현재 마이팀은 카드 상단 고정과 알림 기본 ON 정도로 정의되어 있다. 더 강하게 가려면 홈 최상단을 “스코어보드 목록”이 아니라 **마이팀 브리프**로 보는 편이 맞다.

마이팀 브리프 필수 구성:

- 오늘 경기 상태: 없음 / 예정 / 라이브 / 종료 / 취소
- 상대와 구장
- 경기 전: 시작 시간, 선발, 라인업 공개 여부
- 경기 중: 스코어, 이닝, 주자 상황, 직전 주요 플레이
- 경기 후: 결과, 승패 요약, 눈에 띄는 선수 1~2명
- CTA: 경기 상세 보기 / 알림 켜기 / 예매 보기 / 기록 보기

마이팀 미선택 상태에서는 단순 빈 상태가 아니라 “팀 선택 시 무엇이 달라지는지”를 보여줘야 한다.

### 2.4 라이트팬/코어팬 정보 깊이 분리

한 화면에서 모든 정보를 다 보여주면 앱이 무거워진다. 화면별로 정보 깊이를 명확히 나눠야 한다.

| 사용자 | 1차 화면 | 2차 화면 | 3차 화면 |
| --- | --- | --- | --- |
| 라이트팬 | 홈 브리프, 스코어 카드, 알림 | 경기 상세 요약 | 순위/일정 |
| 코어팬 | 경기 상세 스코어/문자중계 | 박스스코어/라인업 | 기록실/선수 상세 |
| 예매 사용자 | 홈/일정 예매 배지 | 일정 상세 | 알림 설정 |
| 데이터형 팬 | 순위/기록실 요약 | 팀 기록/선수 상세 | 시즌 추이 |

설계 원칙:

- 홈에는 “판단에 필요한 요약”만 둔다.
- 경기 상세에는 “현재 경기 맥락”을 둔다.
- 기록실에는 “시즌/선수 판단”을 둔다.
- 설정에는 “운영/개인화 제어”를 둔다.

## 3. 화면별 기획 보강

### 3.1 홈

현재 홈은 스코어보드 중심이지만, 실제 제품력은 “오늘 내 야구 상황판”으로 잡는 것이 좋다.

보강안:

- 최상단을 `마이팀 브리프`로 고정한다.
- 그 아래 `오늘의 경기` 목록을 둔다.
- 경기 없음 상태에서도 홈이 비지 않게 `다음 경기`, `마이팀 순위`, `리그 주요 기록`을 보여준다.
- 경기 중에는 `최근 주요 플레이` 1줄을 카드에 추가한다.
- 종료 경기에는 예매/알림 CTA를 숨기고, 결과/승리투수/핵심 선수 중심으로 바꾼다.

홈 우선순위:

1. 마이팀 경기 상태
2. 오늘 경기 전체 흐름
3. 바로 탭할 상세 경기
4. 빠른 콘텐츠: 순위/기록/일정 요약

### 3.2 경기 상세

현재 스코어/문자중계/박스스코어/라인업 탭 구조는 적절하다. 보강해야 할 부분은 탭 간 맥락 연결이다.

보강안:

- 상단 고정 영역에 현재 경기 핵심 상태를 항상 유지한다.
- 문자중계 탭은 단순 로그가 아니라 `현재 타석 카드 + 주요 이벤트 타임라인` 구조로 강화한다.
- 박스스코어 탭은 표보다 모바일 카드 우선으로 유지하되, 핵심 지표만 먼저 보여준다.
- 라인업 탭은 선발/교체/불펜 흐름이 보이도록 “경기 중 변동” 표시를 둔다.
- 종료 경기 상세는 첫 진입 탭을 스코어보다 `요약` 또는 `문자중계 주요 이벤트`로 바꾸는 옵션을 검토한다.

추가 검토 탭:

- `요약` 탭: 최종 결과, 승부처, MVP급 선수, 주요 기록을 1스크린에 제공
- 단, MVP 전까지는 별도 탭보다 스코어 탭 상단 섹션으로 넣는 편이 단순하다.

### 3.3 일정

현재 일정은 월간/구장별/팀 필터까지 기능이 강하다. 다음 단계는 “탐색”보다 “내가 언제 보면 되는지”를 강화하는 것이다.

보강안:

- 마이팀 경기만 보는 빠른 토글을 더 상단에 둔다.
- 날짜 셀에 경기 수, 마이팀 경기, 취소/더블헤더 상태를 구분 표시한다.
- 경기 전 일정 카드에는 선발, 예매 오픈, 알림 상태를 배지로 표시한다.
- 경기 종료 카드에는 예매 정보를 숨기고 결과/다음 경기 연결을 둔다.

### 3.4 순위

순위 화면은 표 중심이 맞지만 모바일에서는 정보 밀도 조절이 중요하다.

보강안:

- 기본 열은 `순위 / 팀 / 승패무 / 승률 / 게임차`로 제한한다.
- `최근 10경기`, `연속`, `홈/원정`은 확장 행 또는 상세 보기로 분리한다.
- 마이팀 행은 팀 컬러 좌측 바와 고정 강조를 준다.
- 순위 변동을 제공할 수 있으면 `전일 대비` 표시를 작게 추가한다.

### 3.5 기록실

기록실은 코어팬 락인에 중요하다. 현재 팀 선수/리더보드 구조는 좋지만, 진입점과 요약성이 더 필요하다.

보강안:

- 기록실 첫 화면은 `마이팀 선수 현황`과 `리그 리더`를 함께 보여준다.
- 선수 상세는 시즌 누적보다 `최근 흐름`을 먼저 보여주는 것이 모바일에 맞다.
- 투수/타자 지표는 전문 용어만 나열하지 말고 핵심 3개 지표를 우선한다.
- 홈 빠른 콘텐츠에서 기록실로 자연스럽게 들어가는 선수 카드가 필요하다.

권장 지표:

| 영역 | 기본 지표 | 확장 지표 |
| --- | --- | --- |
| 타자 | 타율, 홈런, 타점, OPS | 출루율, 장타율, 최근 5경기 |
| 투수 | ERA, WHIP, 승/패, 탈삼진 | 이닝, 피안타율, 최근 등판 |

### 3.6 알림

알림은 차별화 핵심인데 현재는 이벤트 목록 중심이다. 사용자가 “너무 많이 올까 봐” 걱정하지 않게 설계해야 한다.

보강안:

- 알림 설정을 `마이팀 기본`, `경기 이벤트`, `예매/일정`, `기록 달성`으로 그룹화한다.
- 각 토글 아래에 실제 발송 예시를 1줄로 둔다.
- `조용한 모드`: 경기 종료/예매만 받기 같은 프리셋을 둔다.
- `코어팬 모드`: 득점/홈런/역전/투수교체/라인업 공개까지 받는 프리셋을 둔다.

추천 프리셋:

| 프리셋 | 대상 | 기본 ON |
| --- | --- | --- |
| 가볍게 보기 | 라이트팬 | 경기 시작, 종료, 득점 |
| 내 팀 집중 | 일반 팬 | 마이팀 득점, 홈런, 역전, 종료, 예매 |
| 풀타임 팔로우 | 코어팬 | 라인업, 이닝 종료, 투수 교체, 주요 기록 |

### 3.7 위젯 / Live Activity

위젯은 Phase 1.5로 정의되어 있지만, 제품 정체성과 강하게 연결된다. “앱을 열지 않아도 마이팀을 본다”가 핵심이다.

보강안:

- 홈 화면 위젯: 다음 경기 / 라이브 스코어 / 최종 결과 3상태
- 잠금화면 위젯: 마이팀 경기 상태와 스코어만 최소 표시
- Live Activity: 라이브 경기 중 이닝/스코어/주자 상태 중심

주의점:

- 위젯은 데이터 신선도 기대치가 높다. 실시간 중계 수준을 약속하면 부담이 크다.
- MVP에서는 “마이팀 경기 상태 확인”까지만 약속하고, 투구별 업데이트는 앱 상세로 연결하는 편이 안전하다.

## 4. 디자인 시스템 보강

### 4.1 현재 방향

현재 디자인 방향은 다크 배경, 팀 컬러, 라이브 레드, Pretendard/SF Pro 조합이다. 방향은 맞다. 보강할 점은 색상보다 **상태 표현 체계**다.

### 4.2 상태 색상 체계

| 상태 | 색상/표현 | 사용 위치 |
| --- | --- | --- |
| 경기 전 | 보조 텍스트 + 시간 배지 | 홈 카드, 일정 |
| 라이브 | `#FF4444` + 작은 점/바 | 홈, 상세 상단, 위젯 |
| 득점/긍정 | `#00C853` | 주요 플레이, 기록 상승 |
| 취소/지연 | 중립 회색 + 명확한 라벨 | 일정, 홈 빈 상태 |
| 마이팀 | 팀 Primary 컬러 | 카드 좌측 바, 선택, CTA |
| 경고/오류 | 레드보다 낮은 채도 | Dev/연결 상태, 사용자 에러 |

라이브 레드는 모든 강조에 쓰면 힘이 빠진다. 라이브와 득점성 이벤트에만 제한해야 한다.

### 4.3 카드 체계

카드는 세 종류로 제한하는 것이 좋다.

| 카드 | 목적 | 높이/밀도 |
| --- | --- | --- |
| Hero Game Card | 마이팀 또는 선택 경기 | 높고 정보 많음 |
| Compact Game Card | 전체 경기 목록 | 낮고 빠른 스캔 |
| Insight Card | 순위/기록/예매/선수 요약 | 짧은 CTA 포함 |

카드마다 라운드/패딩/텍스트 크기가 너무 달라지면 앱이 덜 전문적으로 보인다. 현재 Figma prompt의 카드 16px 라운드는 모바일 스포츠 앱 기준 약간 부드럽다. 실제 구현에서는 주요 카드 12px, 작은 카드 8~10px도 검토할 만하다.

### 4.4 팀 컬러 사용 원칙

팀 컬러는 배경 전체를 덮기보다 “식별 포인트”로 쓰는 편이 좋다.

권장 사용:

- 카드 좌측 3~4px 바
- 선택된 팀 border
- 주요 CTA 배경
- 탭/필터 선택 underline
- 선수/팀 프로필 헤더의 작은 accent

비권장:

- 화면 전체 배경을 팀 컬러로 변경
- 팀 컬러 그라데이션 남발
- 빨간 계열 팀에서 라이브 레드와 충돌하는 강조

### 4.5 타이포그래피

모바일 야구 앱은 숫자 가독성이 중요하다.

권장 기준:

- 스코어 숫자: SF Pro/SF 스타일, Bold, 28~36px
- 이닝/상태: Pretendard Semibold, 12~14px
- 팀명: 13~15px, 말줄임 대비
- 표 데이터: 11~13px, 행 높이 충분히 확보
- 설명 문구: 12~13px, 너무 흐린 회색 금지

### 4.6 이미지 사용

선수 이미지와 팀 로고는 KBO Fans의 체감 품질을 크게 올린다.

보강안:

- 홈 마이팀 브리프에 선발 투수 이미지 1개를 조건부 노출한다.
- 박스스코어/라인업 카드에는 선수 이미지 fallback 품질을 맞춘다.
- 기록실은 “텍스트 리스트”보다 선수 얼굴이 있는 카드가 훨씬 강하다.
- 이미지 실패 시 팀 컬러 기반 이니셜 아바타를 통일한다.

## 5. UI/UX 세부 보강 체크리스트

### 5.1 온보딩

- [ ] 팀 선택 후 달라지는 점 2~3개를 짧게 설명
- [ ] 10개 팀이 한 화면에서 더 많이 보이도록 카드 밀도 조정
- [ ] 건너뛰기 후 홈에서 마이팀 선택 CTA 재노출
- [ ] 팀 선택 CTA는 선택 팀 컬러로 즉시 반응

### 5.2 홈

- [ ] 마이팀 브리프를 홈 최상단 제품 단위로 정의
- [ ] 경기 없음 상태에서도 다음 경기/순위/기록 요약 표시
- [ ] 경기 카드에 최근 주요 플레이 1줄 추가 검토
- [ ] 종료 경기에서 예매 CTA 제거
- [ ] 홈 첫 화면에서 3초 안에 오늘 경기 여부 파악 가능해야 함

### 5.3 경기 상세

- [ ] 상단 경기 상태 sticky 유지
- [ ] 문자중계 현재 타석 카드 정보 계층 재점검
- [ ] 득점/교체/홈런/삼진 이벤트의 시각적 구분 정의
- [ ] 박스스코어는 모바일 카드 우선, 표는 보조
- [ ] 종료 경기 요약 섹션 추가 검토

### 5.4 일정

- [ ] 마이팀 일정 필터를 상단 주요 제어로 승격
- [ ] 날짜 셀에 경기 수/마이팀 경기 여부 표시
- [ ] 예매 오픈/알림 상태를 배지로 표시
- [ ] 우천취소/지연 상태 시각 체계 통일

### 5.5 순위

- [ ] 기본 열을 줄여 모바일 가독성 확보
- [ ] 마이팀 행 강조
- [ ] 확장 정보는 행 펼침 또는 상세로 분리
- [ ] 순위 변동/최근 흐름은 가능할 때만 추가

### 5.6 기록실

- [ ] 기록실 첫 화면에 마이팀/리그 리더를 함께 배치
- [ ] 선수 상세에서 최근 흐름 우선
- [ ] 타자/투수 핵심 지표 3~4개로 1차 요약
- [ ] 홈 빠른 콘텐츠와 기록실 연결 강화

### 5.7 설정/알림

- [ ] 알림 프리셋 추가
- [ ] 각 토글에 발송 시점/예시 문구 추가
- [ ] 마이팀만/전체 경기 범위를 구조적으로 분리
- [ ] 연결 진단은 개발/웹 상태에서만 쉽게 접근

## 6. 우선순위 제안

### P0: 제품 선명도

1. 홈을 `마이팀 브리프 + 오늘 경기` 중심으로 재정의
2. 경기 없음/경기 전/라이브/종료 상태별 홈 콘텐츠 규칙 확정

3. 팀 컬러 사용 범위 제한
4. 선수 이미지 fallback 체계 통일

### P2: 코어팬 락인

1. 경기 상세 요약 섹션
2. 기록실 첫 화면 정보 구조 보강
3. 선수 상세 최근 흐름 중심 재배치

### P3: 확장 경험

1. 위젯 상태별 콘텐츠 정의
2. 예매/일정 알림 강화
3. 공유 가능한 경기 결과 카드
