## 0. 현재 런타임 기준

- 앱은 모든 일반 빌드에서 backend API mode를 기본으로 사용한다.
- Backend API는 API-backed data, snapshot generation, push notification, Live Activity / Dynamic Island sync의 active runtime contract다.
- Flutter 화면 provider는 `USE_BACKEND_API` 미지정 시에도 API mode다. 스크립트/CI는 예측 가능성을 위해 `USE_BACKEND_API=true`를 명시한다.
- Direct KBO mode는 `USE_BACKEND_API=false`를 명시한 upstream parser/debug 전용 경로로 유지한다. 일반 local/dev/release/web/native 빌드나 tester-facing artifact 기본값으로 쓰지 않는다.

## 1. 앱 네비게이션 구조

### Bottom Tab Navigation (5탭)

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│                [화면 콘텐츠 영역]                    │
│                                                     │
├─────────┬─────────┬─────────┬─────────┬────────────┤
│   홈    │   경기   │   기록   │   뉴스   │   설정    │
└─────────┴─────────┴─────────┴─────────┴────────────┘
```

### 화면 전환 모션

- 하단 5탭 이동은 즉시 컷 전환하지 않고, 760ms 안팎의 fade + 부드러운 horizontal slide + 얕은 scale 전환을 사용한다.
- 하단 탭 전환은 탭 순서를 기준으로 좌우 방향을 맞추고, 기존 화면도 아주 약한 parallax/fade로 함께 빠져나가 새 화면이 튀어나오는 느낌을 줄인다. 기본 진입 760ms, 복귀 560ms를 사용한다.
- 경기 상세, 선수 상세, 리더보드, 진단, 업데이트 소식처럼 현재 화면 위로 진입하는 root push 화면은 1000ms iOS식 slide/parallax 전환을 사용한다.
- root push 화면은 이전 화면이 route stack에 있을 때 좌측 edge-swipe로 뒤로갈 수 있어야 한다. 앱 실행 deep link처럼 첫 route로 열린 경우에는 화면의 뒤로가기 버튼이 `/home` 복귀를 담당한다.
- 뉴스 카드/CTA가 `/standings`, `/records`, `/schedule`처럼 shell 탭 화면을 현재 뉴스 화면 위로 `push`하는 경우에도 이전 뉴스 화면으로 좌측 edge-swipe 복귀가 가능해야 한다. 하단 탭을 직접 누르는 `go` 이동은 기존 5탭 전환 모션을 유지한다.
- 부트/온보딩 전환은 콘텐츠 움직임을 최소화한 360ms fade 중심으로 처리한다.
- 홈/일정/뉴스/순위/기록실/선수 상세의 로딩, 에러, 데이터 상태 전환은 360ms 안팎의 공통 fade + vertical slide + 얕은 scale 모션을 사용해 화면 교체를 분명하게 보여준다.
- 경기 카드, 일정 카드, 순위 행, 선수/리더보드 행처럼 반복 리스트로 나타나는 정보는 320ms 이상, index별로 조금 길어지는 등장 모션을 허용하되 스크롤 성능과 정보 밀도를 우선한다.
- 터치 가능한 경기/일정/뉴스/기록실/설정 카드, 홈 보조 카드, 하단 탭, 필터/정렬 chip, 온보딩 팀 카드는 press scale + opacity 피드백을 사용하되 실제 레이아웃 크기는 흔들지 않는다.
- 경기 상세 내부의 스코어 회차 셀, 문자중계 이닝 chip, 박스스코어 팀 토글/선수 카드, 하이라이트 카드도 같은 press 피드백과 짧은 상태 전환을 사용한다.
- 라인업 탭, API 진단, 업데이트 소식처럼 보조 화면도 로딩/오류/완료 상태 전환과 반복 카드 등장에는 공통 fade + 짧은 slide/scale 모션을 사용한다.
- 실시간 점수와 경기 상세 스코어처럼 값이 바뀌는 숫자는 기존 레이아웃 크기를 유지하면서 340ms 안팎의 value swap slide/scale 모션을 적용한다.
- OS 접근성 설정에서 애니메이션 줄이기가 켜진 경우에는 앱 custom 라우팅/상태/터치 피드백 모션을 생략하거나 즉시 전환한다.
- 모션은 야구 정보 스캔을 방해하지 않는 보조 피드백이어야 하며, 카드 크기나 하단 탭 높이를 흔들지 않는다.
- 공통 pressable은 스크린리더에 button/enabled/selected 상태를 전달하고, 웹·키보드 환경에서 Enter/Space 활성화와 눈에 보이는 focus outline을 제공한다. 비활성 컨트롤은 포인터와 키보드 모두 실행되지 않아야 한다.
- 주요 아이콘/텍스트 액션의 최소 터치 높이는 44px, 하단 탭은 48px로 유지한다. 비선택 하단 탭과 필터 라벨은 disabled 색이 아니라 읽을 수 있는 secondary 색을 사용한다.

### 시각 / 카피 톤

- 앱 UI 라벨에는 이모지 텍스트를 쓰지 않는다. 필요한 의미 표시는 Material/SF Symbol 같은 벡터 아이콘, 작은 상태 점, 배지, 팀 컬러로 처리한다.
- 기본 화면 팔레트는 중립 차콜 계열(`#0F0F0F`, `#171717`, `#1D1D1D`, `#292929`, `#373737`)을 사용하고, 팀 컬러와 라이브 레드는 상태를 설명할 때만 제한적으로 쓴다.
- 영어 eyebrow는 데이터/스포츠 관용상 필요한 `LIVE` 정도로 제한하고, `MY TEAM`, `SETTINGS` 같은 장식형 라벨은 한국어 화면 문맥으로 표현한다.
- 과한 그라디언트와 큰 둥근 장식보다 8px 카드, 명확한 정보 계층, 실제 경기 맥락을 우선한다.
- 생성 비주얼은 독립 배너나 삽입 이미지 카드처럼 보이게 두지 않는다. 정상 데이터 화면에서는 필요한 경우 카드/표/헤더의 낮은 opacity background layer로만 통합하고, 독립 `AppArtworkCard`는 empty, retry처럼 화면 상태 자체를 설명하는 경우에만 사용한다.
- 대량 보조 리소스는 리얼/시네마틱 이미지가 아니라 캐주얼 2.5D 스티커형 야구 일러스트를 사용한다. 경기 상세와 설정에는 필요한 경우 WebP 리소스를 낮은 밀도의 보조 레이어로만 쓰고, 온보딩은 팀 선택과 마이팀 미리보기 중심으로 유지한다. 홈은 별도 가로 레일 대신 마이팀 브리프 카드의 낮은 opacity background layer와 실제 팀 로고/경기 행 안에 비주얼을 흡수한다. 일정, 순위, 기록실 정상 화면은 캘린더/경기 목록/순위표/리더보드의 정보 밀도를 우선해 보조 비주얼 rail을 두지 않고, 빈/오류 상태에서만 생성 비주얼을 사용한다.
- 홈의 보조 섹션 카드는 3px 안팎의 얇은 팀/상태 컬러 rail로 containment를 주고, 카드 전체를 강한 색으로 덮지 않는다.
- 헤더 오른쪽 아이콘은 실제 동작이 있는 경우에만 둔다. 홈 레퍼런스 헤더의 알림 아이콘은 설정으로, 검색 아이콘은 기록실로 연결한다.

### 화면 흐름도 (Navigation Flow)

```
[온보딩 - 마이팀 선택]
        │
        ▼
[홈: 마이팀 브리프 + 오늘 경기 + 순위 + 최근 5경기] ──tap 경기 행──▶ [경기 상세]
        │                              ├── 탭: 스코어
        │                              ├── 탭: 문자중계
        │                              ├── 탭: 박스스코어
        │                              └── 탭: 라인업
        │
[일정] ──tap 날짜──▶ [해당일 경기 목록] ──tap──▶ [경기 상세]
        │
[뉴스] ──tap 카드──▶ [경기 상세 / 순위 / 기록실]
        │
[순위] (홈/뉴스 카드에서 진입하는 단일 화면)
        │
[기록실] ──tap 선수 카드──▶ [선수 상세]
        │
[설정: KBO 액션 허브]
   ├── 마이팀 선택/변경
   ├── 화면 모드: 시스템 / 라이트 / 다크
   ├── 푸시 알림 항목별 토글
   ├── 알림함
   └── 세부 설정 및 지원
```

## 1.1 제품 경험 원칙

### 마이팀 데일리 루프

홈은 단순 스코어 목록이 아니라 “오늘 내 팀 야구 상황판”으로 동작한다.

| 시점 | 홈/알림이 우선 제공할 정보 |
|------|-----------------------------|
| 경기 없음 | 다음 경기, 마이팀 순위, 리그 주요 기록 |
| 경기 전 | 상대, 시간, 구장, 선발 투수, 라인업 공개 여부, 예매/알림 CTA |
| 경기 중 | 스코어, 이닝, 주자/아웃/카운트, 직전 주요 플레이 |
| 경기 종료 | 최종 스코어, 승패 요약, 핵심 선수, 박스스코어 진입 |
| 다음 날 | 순위 변동, 마이팀 최근 5경기, 주요 기록 변화 |

### 정보 깊이

- 홈: 3초 안에 오늘 경기 여부와 마이팀 상태를 판단할 수 있어야 한다.
- 경기 상세: 현재 경기 맥락을 유지한 채 스코어/문자중계/박스스코어/라인업을 오간다.
- 기록실: 시즌/선수 판단을 위한 코어팬 화면으로 두고, 홈에서는 요약 카드만 노출한다.
- 설정: 다른 탭의 정보 요약과 중복 이동 버튼을 반복하지 않고 마이팀 선택, 알림함, 앱 관리 같은 실제 액션만 모은다.

**UI 요소**:
| 요소 | 설명 |
|------|------|
| 팀 로고 그리드 | 10개 팀. 모바일 390px 기준 2열, 360px 미만 또는 150% 이상 글자 크기에서는 1열로 전환하고 카드 높이를 글자 크기에 맞춘다. 넓은 화면에서는 3열까지 확장한다. KBO CDN `emblem/regular/fixed/emblem_{TEAM}_L.png` 이미지 사용 |
| 선택 상태 | 선택 시 팀 컬러 border + 체크 아이콘. 1팀만 선택 가능하며 스크린리더에도 selected 상태를 전달 |
| 시작하기 버튼 | 팀 선택 시 활성화 (팀 컬러로 변경). 저장/초기 진입 준비 중에는 `시작 중입니다`와 spinner를 표시하고 중복 탭을 막는다 |
| 건너뛰기 | 팀 미선택으로 진행. 설정에서 나중에 선택 가능. 최소 44px 터치 높이와 활성 텍스트 대비를 유지하고 저장 중에는 중복 입력을 막는다 |
| 선택 효과 설명 | 팀 선택 시 홈 브리프, 알림, 일정 필터가 개인화된다는 점을 2~3줄로 짧게 설명 |
| 장식 이미지 | 온보딩 상단에 독립 배너/경기장 이미지 카드를 두지 않는다 |

**인터랙션**:
- 팀 탭 → 선택 토글 (이전 선택 해제)
- 시작하기 → 진행 상태 표시 → SharedPreferences에 `myTeam` 저장 → 홈 화면 이동
- 건너뛰기 → 진행 상태 표시 → `myTeam = null` → 홈 화면 이동
- 2회차 이후 앱 실행 → 온보딩 스킵, 바로 홈
- 건너뛰기 사용자는 홈 상단과 설정에서 마이팀 선택 CTA를 다시 노출
- 홈의 마이팀 선택 CTA로 edit 온보딩에 들어오면 선택 완료/취소 모두 홈으로 돌아간다. 설정에서 들어오면 설정으로 돌아간다.
- 최초 온보딩을 완료한 설치는 현재 버전을 업데이트 소식 기준선으로 기록해 첫 홈을 팝업으로 막지 않는다.

- 홈에서 경기 행이나 마이팀 오늘 경기 카드를 열 때는 `gameProvider(gameId)`를 invalidate/read 한 뒤 경기 상세로 push 한다. 홈 위에는 `경기 정보 갱신 중` 로딩과 게이지를 표시한다. `gameProvider(gameId)`가 4초 안에 준비되지 않으면 이미 홈에 표시된 경기정보를 `extra`로 넘겨 먼저 상세에 들어가며, 상세 화면의 자체 provider refresh가 이후 최신화를 담당한다. 첫 탭 provider와 선수사진 cache warm-up은 병렬 background 작업으로 시작하되, 실패/timeout이면 진입을 막지 않고 Dev Console 경고로만 남긴다.
- 일정 화면에서 경기 카드를 열 때도 바로 `/game/{gameId}`로 push하지 않고 `gameProvider(gameId)`를 먼저 갱신한다. 갱신된 경기가 live이면 `relayDataProvider(gameId)`와 선수 이미지 source/cache warm-up을 background로 시작하고 `tab=relay`로 이동한다. 상세 갱신 실패 시에도 일정 카드가 live이면 `tab=relay`를 유지한다.

**인터랙션**:
- Pull-to-refresh → 스코어 수동 새로고침
- 경기 카드 탭 → 경기 상세 화면 이동
- 경기 중일 때 → 8초 자동 갱신 (Adaptive Polling)
- 날짜 탭 → 날짜 피커 열림 → 다른 날짜 스코어보드 조회

**데이터 바인딩**:
```
GET /api/scoreboard?date=2026-03-28
→ 경기 목록 [{gameId, away, home, score, inning, status, ...}]
```

**운영 메모**:
- 서버는 날짜별 live scoreboard 응답을 `8초 TTL` 캐시로 보관한다.
- 운영 sync worker는 live scoreboard 요약을 8초 fresh window의 runtime state로 저장하고, `/scoreboard/home`은 이 값이 fresh일 때 원천 KBO 수집 없이 즉시 반환할 수 있다. 이 runtime state는 snapshot fallback이 아니며 stale이면 무시하고 기존 fresh-first 원천 조회/오류 정책으로 돌아간다.
- 예정 경기일 때 KBO scoreboard 세부 테이블이 비어도 홈 화면은 fallback payload 로 렌더링한다.
- 예정 경기는 YouTube 검색을 생략하고 KBO 공식 하이라이트 링크만 유지한다.
- 진단 화면은 `health / scoreboard / schedule / push` 상태를 한 번에 확인하고, push 초기화 실패 사유를 표시한다.
- 순위 히스토리 조회는 시즌별 번들 스냅샷 fallback(`2001~현재`)을 사용할 수 있다. 명시적 API-backed current 경로의 실패는 번들 snapshot으로 숨기지 않는다.

### 2.2.1 기록실

**목적**: 리그 핵심 리더를 먼저 해석하고, 이어서 마이팀/팀별 선수 현황과 간단 기록을 빠르게 확인

**핵심 구성**:
| 요소 | 설명 |
|------|------|
| 오늘 읽을 기록 | 리그 overview 응답의 `todayHitter` / `todayPitcher` 대표를 함께 노출하고, AVG/HR/OPS/wRC+/ERA 선두를 조합해 가장 강한 1위 선수와 선수 이미지를 보여준다. 하단 요약은 내부 source confidence나 데이터 개수 대신 타율/홈런/ERA 등 실제 리더와 2위 격차를 먼저 노출 |
| 지표 spotlight | AVG/HR/OPS/wRC+/ERA/다승/세이브/탈삼진을 가로 rail로 보여주고, 각 카드에 1위 순위 badge, 선수/팀/값/2위와 격차를 표시 |
| 마운드 체크 | 투수 지표가 가로 rail 끝에 묻히지 않도록 ERA, 다승, 세이브, 탈삼진 리더를 별도 compact panel로 표시하고 각 지표별 전체 리더보드로 연결 |
| 리그 리더보드 preview | `타자` / `투수` 탭으로 먼저 나눈 뒤 타자는 AVG/HR/OPS/wRC+, 투수는 ERA/다승/세이브/탈삼진 지표를 전환하며 TOP 3 table row를 표시하고 전체 리더보드 화면으로 연결 |
| 팀 기록실 진입 | 검색 전 `팀 기록실` 섹션 헤더를 두고 마이팀을 우선 정렬한 팀 목록으로 연결 |
| 상단 요약 | 엔트리 수 / 엔트리 제외 수 |
| 선수 탭 | `야수` / `투수` 전환 |
| 필터 | `전체` / `엔트리` / `엔트리 제외` |
| 정렬 | 야수는 `이름 / 타율 / OPS`, 투수는 `이름 / ERA / WHIP` |
| 선수 카드 | 이름, 등번호, 포지션, 상태 배지, 간단 기록 |
| 상태 배지 | `정상`, `부상`, `엔트리 제외` |
| 상태 메모 | 부상 이탈, 재활, 컨디션 조정 등 표시 |

**리스트 구조**:
- 팀 엔트리
- 엔트리 제외 / 부상 이탈

**인터랙션**:
- 리그 지표 카드 탭 → 지표별 전체 리더보드 화면 이동
- 리그 리더보드 preview 역할 탭 → 같은 화면 안에서 타자/투수 지표 묶음 전환
- 리그 리더보드 preview 지표 탭 → 같은 화면 안에서 해당 지표 TOP3 table 전환
- 전체 리더보드 화면 → `타자` / `투수` 탭과 역할별 지표 chip으로 여러 리그 지표를 뒤로 가기 없이 전환
- 팀 카드 탭 → 팀 기록실 화면 이동
- 선수 카드 탭 → 선수 상세 화면 이동

**데이터 바인딩**:
```
GET /api/records/overview?season=2026
→ 오늘 읽을 기록 / 지표 spotlight / 마운드 체크 / 리더보드 preview
→ leaders: avg, hr, ops, opsPlus, era, wins, saves, strikeouts

GET /api/team/{teamId}/players?season=2026
→ 팀 엔트리 / 말소 / 간단 시즌 지표 / 최근 기록 요약
```

**운영 메모**:
- 기록실 팀 데이터와 팀 스탯은 팀/시즌 기준 `5분 TTL` 캐시를 사용한다.
- 앱은 기록실 로딩 완료 시간을 Dev Console 과 `/api/metrics/client` 로 함께 기록한다.
- 기록실 요약/리더보드 번들 스냅샷은 요청한 시즌과 정확히 일치할 때만 사용한다.
- 현재 시즌 기록실 요약 번들은 `generatedAt` 기준 6시간 이내일 때만 fallback 으로 사용한다.
- 기록실 요약/리더보드 API cache 와 기기 snapshot 은 핵심 리더보드 첫 항목이 1위일 때만 재사용하거나 저장한다.
- 명시적 API-backed 앱 모드에서는 현재 시즌 기록실 요약/리더보드 API 실패를 앱 번들 bootstrap, fresh local API cache, backend current snapshot 으로 대체하지 않는다.
- 리더보드 API/cache shape 오류는 현재 시즌 실패로 노출하되, 화면에는 내부 cache key나 `Bad state` 전문을 표시하지 않고 공통 사용자 오류 문구를 사용한다.
- 다른 시즌 기록으로 대체 표시하지 않는다. exact snapshot 이 없거나 비어 있으면 빈 상태/오류를 노출해 가짜 리더가 재유입되지 않게 한다.
- KBO 선수 기록 원천은 2001년 이하 요청에서 현재 시즌 rows를 반환할 수 있어, 앱 기록실 시즌 선택과 backend/direct 기록실 크롤링은 2002년 이후만 지원한다.
- 팀 선수/팀 스탯 local asset 은 요청한 팀/시즌의 exact snapshot 만 사용한다. 해당 시즌 snapshot 이 없거나 팀 스탯의 타격/투구 중 한쪽만 있으면 다른 시즌 데이터를 빌리지 않고 빈 상태로 처리한다.
- 명시적 API-backed current 경로에서 현재 시즌 팀 선수/팀 스탯/선수 상세 실패는 backend/app/device snapshot 으로 대체하지 않는다. 과거 시즌만 저장 snapshot 과 cached-first 조회를 허용한다.

### 2.2.2 선수 상세

**목적**: 특정 선수의 프로필과 시즌/최근 기록 확인

**핵심 구성**:
| 요소 | 설명 |
|------|------|
| 프로필 카드 | 등번호, 팀, 포지션, 투타, 신체 조건 |
| 주요 기록 | 대표 지표, 시즌 기록 요약 |
| 최근 기록 | 최근 경기별 간단한 결과 |
| 노트 | 부상 메모, 최근 흐름, 역할 설명 |

**데이터 바인딩**:
```
GET /api/player/{playerId}?season=2026
→ 선수 프로필 / 시즌 기록 / 최근 기록
```

**운영 메모**:
- 선수 프로필과 시즌 누적 기록은 저장된 선수/시즌 기준 스냅샷이 있으면 우선 사용할 수 있다.
- 최근 경기 기록은 최근 N경기 요약을 미리 정규화해 저장하고, 앱은 마지막 스냅샷을 먼저 렌더링한 뒤 필요 시 백그라운드 재검증만 수행한다.
- 당일 live 경기 중 변할 수 있는 오늘 경기 누적값만 짧은 TTL 또는 live 소스와 병행하고, 과거 날짜 기록은 원천 재크롤링 없이 저장된 히스토리 레코드를 우선 조회한다.

### 2.3 경기 상세

**목적**: 선택한 경기의 심층 정보 (문자중계, 박스스코어, 라인업)

#### 공통 레이아웃

```
┌─────────────────────────────────────┐
│  ← 뒤로    KT vs LG    잠실 23,750 │
├─────────────────────────────────────┤
│  [KT 로고]     6 : 2     [LG 로고] │
│   KT 위즈     4회초      LG 트윈스  │
├─────────────────────────────────────┤
│  스코어 │ 문자중계 │ 박스스코어│라인업│
├─────────────────────────────────────┤
│                                     │
│        [선택된 탭의 콘텐츠]           │
│                                     │
└─────────────────────────────────────┘
```

**상단 고정 영역**:
- 뒤로 버튼 + 경기장명 + 관중수
- 양팀 로고 + 팀명 + 현재 스코어 (큰 폰트)
- 현재 이닝/경기 상태
- 종료 경기 상단 중앙 상태는 마지막 회차(`9회`, `연장 10회` 등)가 아니라 `경기 종료`로 표시한다.
- 예매 정보 카드: 경기 전 상태에서만 노출하되, 경기 상세에서는 경기 시작 2시간 전부터 숨김. 예매처 / 예매 시작시간 / 예매처 바로가기 / 예매 오픈 알림 토글
- 하이라이트 카드: 유튜브 썸네일 / 영상 제목 / `KBO 하이라이트` / `바로 재생` / `공식 영상` 버튼
- 진행/종료/취소/서스펜디드 경기에서는 예매 정보 대신 현재 경기 상태, 최종 결과, 승패 요약, 핵심 선수, 주요 이벤트 요약을 우선 노출

**탭 간 맥락 연결 원칙**:
- 상단 경기 상태는 모든 탭에서 sticky 유지한다.
- 문자중계의 주요 이벤트는 스코어 탭 요약과 박스스코어 핵심 카드에 연결된다.
- 박스스코어/라인업 선수 카드는 기록실 또는 선수 상세 진입점으로 사용한다.
- 경기 상세의 팀 로고는 scorebug/문자중계/박스스코어/라인업 모두 공용 이미지 위젯을 사용하고, `BoxFit.contain` + padding으로 로고가 잘리지 않게 표시한다. 선수 row는 API/player lookup 또는 endpoint response의 `imageUrl`을 우선 표시하고, `imageUrl`이 비었지만 선수 `id`가 있으면 KBO player image URL을 구성해 사용한다.
- 종료 경기 첫 화면은 스코어 탭 상단에 결과 요약 섹션을 먼저 둔다. 별도 `요약` 탭은 MVP 이후 검토한다.
- 종료/과거 경기의 스코어 탭은 하이라이트를 명시 요청 없이 자동 조회한다. YouTube 영상 ID가 있으면 앱 안 인라인 플레이어로 재생하고, 검색 결과가 비었거나 영상 ID가 없으면 유튜브 검색/공식 하이라이트 링크를 앱 안 브라우저로 연다.
- 종료/과거 경기의 박스스코어, 라인업, 문자중계는 완성된 backend snapshot을 우선 사용하고, snapshot이 비었거나 현재/미래 경기일 때만 live 원천 조회로 넘어간다.
- 홈/일정에서 전달받은 기존 경기정보가 있으면 첫 단건 조회 또는 이후 앱 복귀/주기 refresh가 실패해도 전체 화면 오류로 전환하지 않고 마지막 경기 상세를 유지한다. 이때 `갱신 지연`, `기존 경기 정보를 유지하고 있습니다`, `다시 시도`를 표시하고 성공하면 자동으로 해제한다. 처음부터 경기정보가 전혀 없는 cold 실패만 오류/미존재 상태를 표시한다.
- `/game/{gameId}?tab=relay&focus=relay` 진입은 sticky 탭 높이 48px를 남겨 문자중계 첫 요약이 탭 아래에 가려지지 않게 한다.
- 후보 기능: 경기/마이팀 선수 기록 인사이트는 `docs/PLAYER_RECORD_INSIGHTS_PLAN_2026-05-20.md`의 검증/구현 기준으로 별도 승인 후 확정한다. 현재 앱/API 계약에는 포함하지 않는다.

| 중계 아이템 | 타석 결과 카드. 역순 정렬 (최신이 위), 주체 선수 아바타를 같이 표시 |
| 이벤트 강조 | 득점 / 홈런 / 교체 / 삼진 / 일반 플레이를 배지와 컬러로 구분 |
| 주요 장면 필터 | `전체 / 득점 / 안타 / 홈런 / 교체` 칩에 현재 카운트를 표시하고, 선택 시 해당 이벤트 카드만 표시. `득점` 필터의 상세 원문 카드에는 원문에서 확인 가능한 경우 `친 선수`와 `홈인` 주자를 별도 라인으로 보여준다 |
| 새 중계 배너 | 사용자가 상단에서 떨어져 있을 때 새 seq가 들어오면 `새 중계가 들어왔습니다` 배너와 `최신 보기` 액션 표시 |
| 타석 카드 레이아웃 | 선택한 회차/필터에서는 타석별 카드에 선수 프로필, 상대투수/상대팀, 플레이 결과 바, 순번형 투구 로그를 묶어서 표시 |
| 투구 로그 | `N구` 단위 로그에 볼/스트라이크/파울 결과 배지와 누적 볼카운트 시각화 표시 |
| 투구 시퀀스 | 각 타석의 볼/스트라이크/파울 순서 표시 |
| 생성 비주얼 | 문자중계 빈 상태와 공식 원문 fallback 요약에는 `live_relay_field` 생성 이미지를 사용하되, 로고/구단 엠블럼/읽을 수 있는 임의 텍스트는 포함하지 않는다 |

**인터랙션**:
- 자동 스크롤 → 새 중계 추가 시 상단에 삽입 + 부드러운 애니메이션
- 회차 선택 → `전체 / N회초 / N회말` 칩을 눌러 해당 회차 문자중계만 필터링. 원문 이닝 전환 텍스트에 팀 공격 문구나 구분선이 포함되어도 칩 라벨은 `N회초/N회말`만 노출
- 주요 장면 선택 → `전체 / 득점 / 안타 / 홈런 / 교체` 칩을 눌러 해당 이벤트만 확인. 필터 결과가 비면 조건별 빈 상태를 노출
- 새 중계 도착 → 사용자가 최신 영역을 보고 있지 않을 때 상단 복귀 배너를 띄우고, 탭하면 전체/최신 상태로 돌아간다
- LIVE 경기에서는 홈 scoreboard와 경기 상세 기본 탭은 8초, 문자중계 foreground 갱신은 5초 cadence로 맞춘다.
- 경기 종료 시 → "경기가 종료되었습니다" 배너
- LIVE 경기에서는 relay 원천 실패를 득점 요약이나 과거 snapshot 으로 대체하지 않고 실패/미지원 상태로 노출
- 종료 경기라도 원문 relay 확보가 가능하면 득점 요약이 아니라 실제 play-by-play와 교체 로그를 우선 표시하고, 실패 시에만 summary fallback 사용. 단 `currentAtBat`은 non-LIVE 상태에서 항상 `null`로 취급해 B/S/O와 타자/투수 matchup을 지운다.

**데이터 바인딩**:
```
GET /api/game/{gameId}/relay
→ {currentAtBat: {batter: {name, imageUrl, ...}, pitcher: {name, imageUrl, ...}, ballCount, ...}, relayItems: [{inning, half, text, event, ...}]}
```
- `currentAtBat`은 LIVE 경기 전용이다. 종료/취소/서스펜디드 경기에서는 snapshot이나 공식 relay HTML에 마지막 타석이 남아 있어도 API와 앱 UI가 이를 진행 중 상태로 표시하지 않는다.

**상태 처리**:
- 공식 박스스코어 rows가 아직 없으면 “공식 박스스코어 업데이트 전입니다”를 표시한다.
- live 경기에서 KBO 공식 박스스코어 endpoint가 아직 비어 있어도 KBO main list가 현재 타자/투수/선발투수를 제공하면 `liveContextAvailable=true`로 `실시간 기록 추적` 상태를 표시한다.
- live context row는 공식 누적 기록처럼 임의의 0값을 표시하지 않고 기록 셀을 `-`로 둔다. 다만 relay currentAtBat의 오늘 타석 결과로 타수/안타를 계산할 수 있으면 해당 타자 row에는 계산된 타수/안타/타율을 표시하고, 타점/득점처럼 확정하지 못한 값은 `-`로 유지한다.
- backend API와 direct KBO mode 모두 live 경기의 선발/현재 투수 이름만 확인되고 이닝/누적 기록이 비어 있는 placeholder 투수 row는 박스스코어 기록처럼 표시하지 않는다.
- 타자 row는 이름/타순이 있으면 0타수/0안타처럼 값이 0이어도 공식 박스스코어 row로 표시할 수 있다.

**인터랙션**:
- 팀 토글 탭 → 어웨이 ↔ 홈 전환
- 선수 이름 탭 → (Phase 2) 선수 상세 프로필로 이동
- 테이블 가로 스크롤 → 추가 스탯 표시 (OPS, ERA 등은 Phase 2)

**데이터 바인딩**:
```
GET /api/game/{gameId}/boxscore
→ {away: {batters: [...], pitchers: [...]}, home: {batters: [...], pitchers: [...]}}
```

| 보기 전환 | 마이팀 선택 시 `내 팀 먼저 보기`, 미선택 시 `달력 보기`, 그리고 `구장별` / `매치업` segmented control. 선택 상태를 스크린리더에 전달하며, 매치업은 시즌 전체 일정에서 선택한 두 팀이 모두 포함된 경기를 모아 보여준다 |
| 캘린더 그리드 | 경기 있는 날은 얇은 live-red outline으로 날짜를 감싸고, 날짜 아래 4px dot을 둔다. 마이팀 경기일 dot은 action blue, 일반 경기일 dot은 muted gray로 표시 |
| 선택된 날짜 | live-red fill + 더 강한 outline으로 하이라이트하고, 선택 날짜 범례는 white dot으로 설명 |
| 경기 목록 | 선택 날짜의 경기 리스트. 시간 + 상태(`경기 전/경기 중/경기 종료`) + 팀 로고 + 점수 또는 `vs` + 구장을 8px radius dark card에 조밀하게 배치. 저장된 마이팀 경기 카드는 팀 컬러 좌측 바, 강조 테두리, `마이팀` 배지로 일반 경기와 구분한다 |
| 마이팀 필터 | 상단 주요 제어로 배치. 전체 / 마이팀 / 마이팀 제외 |
| 구장별 퀵링크 | 구장별 보기 상단에 구장명 + 경기 수 칩을 표시. 탭하면 해당 구장 섹션으로 즉시 스크롤 |
| 매치업 팀 선택 | `팀 1`, `팀 2` 가로 팀 chip row에서 두 팀을 선택한다. 같은 팀 중복 선택은 포인터와 키보드 모두 비활성화하고, 마이팀이 있으면 `팀 1` 기본값으로 사용한다 |
| 매치업 목록 | 선택한 두 팀의 남은 맞대결을 홈/원정 무관으로 모아 날짜 라벨이 있는 일정 카드 목록으로 표시한다. 오늘을 포함한 앞으로 남은 경기만 오늘 기준 가까운 날짜순으로 정렬한다. 남은 경기가 없으면 매치업 빈 상태를 보여준다 |
| 예매 정보 | 예정 경기 카드에 예매처 + 예매 시작시간 + 알림 상태 배지 표시 |
| 진행/종료 경기 | 예매 정보는 숨기고 경기 상태/결과/다음 경기 연결을 표시 |
| 빈 상태 비주얼 | 날짜 미선택, 선택일 경기 없음, 구장별 일정 없음, 매치업 일정 없음 상태는 `schedule_empty_calendar` 생성 이미지와 짧은 안내 문구를 함께 표시 |

**인터랙션**:
- 날짜 탭 → 하단 경기 목록 갱신
- 캘린더 그리드에 보이는 이전/다음달 날짜를 탭하면 해당 월로 자동 전환하고, 탭한 날짜를 선택한다.
- 경기 항목 탭 → 경기 상세 화면 이동 (과거 경기 = 결과, 미래 = 예정)
- 좌우 스와이프 → 월 전환. 헤더 버튼/오늘 버튼으로 월을 이동할 때는 380ms 안팎의 ease-in-out PageView 전환을 사용한다.
- 월 헤더는 생성 비주얼 없이 현재 월, 이전/다음/오늘 컨트롤만 compact하게 노출해 캘린더와 경기 목록이 첫 화면에서 더 많이 보이게 한다.
- 필터를 고른 뒤 구장별/매치업 보기로 전환해도 월 헤더와 세 컨트롤은 상단 화면 안에 유지한다. 보기 전환 전 남은 포커스는 해제해 웹 viewport가 선택 칩을 따라 위로 밀리지 않게 한다.
- 캘린더 모드의 필터, 범례, 캘린더, 선택일 경기 목록은 하나의 세로 스크롤 표면으로 묶어 어느 영역에서 위아래로 밀어도 경기 목록 스크롤이 자연스럽게 이어지게 한다.
- 이미 선택된 하단 `일정` 탭 재탭 → 현재 선택 월/날짜 유지
- 구장별 보기에서 구장 퀵링크 탭 → 해당 구장 일정 섹션으로 스크롤
- 매치업 보기에서 팀 chip 탭 → 선택한 두 팀의 시즌 전체 맞대결 목록으로 즉시 필터링
- 오늘 버튼 → 오늘 날짜로 복귀
- 구장별/매치업의 현재 월 API 실패는 `일정 없음`으로 숨기지 않고 오류와 `다시 시도`를 표시한다.

**데이터 바인딩**:
```
GET /api/schedule?month=2026-03
→ {days: [{date, games: [{gameId, time, away, home, awayScore, homeScore, stadium, status, ticketInfo}]}]}
```
- 매치업 보기는 별도 endpoint를 만들지 않고 시즌 월간 일정 응답들을 앱에서 합친 뒤 `away.teamId` / `home.teamId`를 홈/원정 무관으로 필터링한다.

**운영 메모**:
- 월간 일정은 월 단위 prefetch/cache 를 사용하고, 지난 날짜 경기 결과는 경기 종료 후 저장된 schedule snapshot 을 우선 사용한다.
- 과거 경기 일정/결과 조회는 live scoreboard 재수집이 아니라 저장된 경기 결과와 예매/구장 메타를 재사용해 즉시 응답한다.

│  경기 · 순위 · 기록 · 마이팀            │
├─────────────────────────────────────┤
│  주요 소식                            │

│  2  [로고] 선두가 위태로운 LG 트윈스    │

│                                     │

│                                     │

├──────┬──────┬──────┬──────┬──────┤
│ 홈   │ 경기 │ 기록 │ 뉴스 │ 설정 │

**UI 요소**:
| 요소 | 설명 |
|------|------|
| 헤더 | 기준일, `뉴스` title, 새로고침 버튼 |
| 편집 리드 | `주요 소식` 아래 먼저 볼 3개 카드를 rank row로 배치. `homeAggregate.kboBrief.title/subtitle`은 뉴스 화면에서 직접 노출하지 않고, 경기 → 순위 → 기록 → 마이팀 순서로 우선 정렬 |
| 필터 | 전체 / 경기 / 순위 / 기록 / 마이팀. 레퍼런스형 segmented row와 선택 탭 배경 highlight로 노출 |
| 뉴스 row | `HomeKboBriefItem`, `HomeAggregate.quickItems`, `HomeAggregate.standingsPreview`, 마이팀 브리프/최근 경기 요약을 기사형 row로 변환. 순위표가 있으면 10팀 순위, 순위권 구도, 승수 페이스, 상위권 연패/중하위권 연승 같은 특이 흐름을 함께 만들어 전체 탭의 `최신 뉴스` 목록이 25개 이상 남도록 한다. 홈런왕 quick item과 순위표 경기 수가 함께 있으면 144경기 기준 홈런 페이스도 추가한다. 좌측은 선수 이미지 또는 reference team logo를 우선 사용하고, 팀명 초성 조합 같은 임의 약칭은 만들지 않는다 |
| 빈 상태 | aggregate에 표시 가능한 brief item이 없으면 `오늘 보여줄 뉴스가 없습니다`와 `일정 보기` CTA를 보여준다. 필터 결과만 비어 있으면 해당 필터 empty state와 전체 보기 동선을 둔다 |
| 오류 상태 | 홈 aggregate 실패 시 별도 기사/placeholder를 만들지 않고 재시도 카드만 보여준다 |

**인터랙션**:
- 하단 `뉴스` 탭 → `/news`
- 카드 탭 → app route sanitizer가 승인한 item route 기준으로 경기 상세, `/standings`, `/records` 계열 화면으로 이동. 외부/미지원 route는 뉴스 브리프 fallback으로 보정하고, push stack이 있는 경우 좌측 edge-swipe로 뉴스 화면에 복귀할 수 있게 한다.
- Pull-to-refresh / refresh icon → 해당 날짜 `homeAggregateProvider` 재조회
- `/news`는 `/standings`를 임시 재사용하지 않는다. 순위 화면은 홈/뉴스 카드에서 들어가는 별도 화면으로 유지한다.

**데이터 바인딩**:
```
homeAggregateProvider("{yyyy-MM-dd}|{myTeamId}")
→ HomeAggregate.kboBrief.items
→ HomeAggregate.quickItems
→ HomeAggregate.standingsPreview
→ HomeAggregate.myTeamBrief
→ HomeAggregate.myTeamBrief.recentSummaries
```

**운영 메모**:
- 뉴스 탭은 외부 기사 크롤링 없이 현재 앱이 검증하는 스코어보드/순위/기록실 aggregate에서 만든 짧은 브리프만 보여준다.
- 계산형 소식은 이미 표시 가능한 수치에서만 만든다. 홈런/승수 페이스는 `wins + losses + draws` 경기 수가 1 이상일 때만 노출하고, 새 API 조회나 추정용 임의 데이터를 만들지 않는다.
- 팀 ERA 대비 불펜 ERA처럼 세부 팀 지표 간 반전 카드는 해당 지표가 `/home` aggregate 또는 별도 검증된 팀 스탯 계약으로 들어온 뒤 자동 생성한다. 현재 뉴스 탭은 standings/quickItems/kboBrief에 이미 포함된 데이터만 재가공한다.
- `1위 LG 트윈스` 같은 건조한 순위 나열 대신 `선두가 위태로운 LG 트윈스`, `선두 추격하는 한화 이글스`처럼 데이터 기반 기사형 제목을 쓴다. 외부 기사 출처를 가장하거나 데이터 없는 fake source는 만들지 않고, 데이터가 없으면 빈 상태를 노출한다.

| 순위 레이스 비주얼 | `standings_race` 생성 이미지는 별도 상단 스트립 대신 순위 요약 rail 안의 낮은 opacity 배경으로 통합해 화면 맥락을 강화 |

| 빈 상태 | 선택 시즌 순위 배열이 비어 있으면 헤더 행만 남기지 않고 `standings_race` 기반 artwork empty state와 `다시 확인` CTA를 보여준다 |
| 업데이트 시간 | 데이터 갱신 시각 표시 |
| 확장 정보 | 최근 10경기, 연속, 홈/원정은 행 펼침 또는 상세 보기에서 노출 |

**인터랙션**:
- 시즌 선택 → `GET /api/standings?season={YYYY}`로 해당 연도 순위 조회
- Pull-to-refresh → 순위 갱신
- (Phase 2) 팀 탭 → 팀 상세 (상대 전적, 최근 성적 등)

**데이터 바인딩**:
```
GET /api/standings?season=2026
→ [{rank, teamId, teamName, wins, losses, draws, pct, gb, streak}]
```

**운영 메모**:
- 순위는 latest 응답만 짧게 캐시하는 것을 넘어서, 시즌 중 하루 여러 번 standings snapshot 을 저장해 과거 날짜 기준 순위 회고가 가능하도록 설계한다.
- 앱 기본 화면은 최신 snapshot 을 즉시 보여주고, 당일 경기 진행 중에만 주기적 재계산 또는 원천 재수집을 허용한다.
- 순위탭의 과거 시즌 선택은 historical standings 경로로 처리하며, API-backed 모드는 cached-first / snapshot fallback 을 사용하고 direct 모드는 KBO `seasonId` 요청을 사용한다.

**UI 요소**:

|------|------|
| 마이팀 | 현재 선택 팀과 `마이팀 선택/변경` 버튼만 표시. 순위, 최근 5경기, 오늘 경기 여부는 홈/일정/순위 탭에서만 다룬다 |

| 푸시 알림 | 설정 첫 화면에서 프리셋을 먼저 고르지 않고, `경기 전후`와 `경기 중` 항목별 토글을 바로 켜고 끈다. 마이팀이 있으면 켜진 항목 수 또는 `모두 꺼짐`, 마이팀이 없으면 `마이팀 미선택`으로 표시한다. 무팀 상태에서도 항목을 미리 설정할 수 있고 직접 팔로우한 경기 알림은 별도 동작함을 안내한다 |
| 알림함 | 수신된 push 목록으로 진입하는 버튼. 설정에서는 최신 알림 본문을 미리 펼치지 않고 unread count만 보조 상태로 둔다 |
| 경기별 알림 범위 | 기본 대상은 마이팀 경기다. 마이팀 경기 topic과 마이팀 외 선택 경기 `*_GAME_{gameId}` topic 모두 현재 켜진 moment만 구독한다 |
| 라이브 경기 알림 | 마이팀 live/라인업 공개 예정/시작 10분 전 예정 경기 자동 선택 또는 현재 경기 상세에서 사용자가 직접 시작하는 Live Activity / Android Live Update 세션 |
| 세부 설정 및 지원 | API 진단, 플랫폼 앱 메타데이터의 실제 버전, 최근 업데이트 소식, 앱 내 법적 문서, 오픈소스 라이선스 페이지, 지원 메일 연결 |

**권한 / 등록 규칙**:
- 앱은 마이팀이 선택된 non-local 환경에서 최초 1회 OS 알림 권한을 요청하고 FCM token/topic registration을 `/push/register`로 동기화한다.
- 기존 사용자가 이미 마이팀을 선택한 상태로 앱을 열면 부트스트랩 이후 같은 자동 동기화를 시도한다. 신규 사용자는 마이팀 선택 직후 같은 경로를 탄다.
- 마이팀이 선택된 사용자의 기본 구독 범위는 마이팀 경기지만, 저장된 delivery/off와 세부 토글을 존중한다. 꺼진 moment는 마이팀 team topic에도 포함하지 않는다.
- `followedGameIds`가 있으면 마이팀 외 경기만 켜진 game moment에 대해 `*_GAME_{gameId}` topic으로 추가한다. 선택한 경기가 마이팀 경기이면 같은 moment의 GAME topic을 만들지 않고 team topic만 유지해 중복 수신을 피한다.
- `allGames=true` 같은 legacy 값이 남아 있어도 game moment는 `*_ALL` topic을 만들지 않는다. 경기 시작/득점/라인업/이닝/타석 등 경기 알림은 마이팀 team topic 또는 사용자가 직접 `푸쉬 중계 받기`를 누른 selected-game `*_GAME_{gameId}` topic만 사용한다.
- 앱 registration의 `baseball_info`도 마이팀 topic을 기본으로 하며, 경기 단건 알림처럼 `followedGameIds`로 GAME topic을 만들지 않는다.
- `inning_change`도 켜져 있으면 마이팀 경기와 마이팀 외 선택 경기 topic에 포함한다.
- local/web 환경은 자동 권한 요청을 하지 않고, 경기 상세의 `푸쉬 중계 받기` 같은 명시적 동작은 계속 수동 sync 진입점으로 유지한다.
- 화면 모드 선택은 `SharedPreferences`의 `appearance.theme_mode`에 `system` / `light` / `dark` 값으로 저장한다. 저장값이 없는 기존 설치는 현재 앱 경험을 보존하기 위해 `dark`를 기본값으로 사용한다.

**카피 원칙**:
- 설정 화면은 설명형 정보 카드보다 실제 이동/설정 버튼을 우선한다. 홈/일정/순위/기록/뉴스 탭에서 이미 노출되는 경기 요약, 순위, 최근 5경기, 기록/뉴스 브리프는 설정에서 반복하지 않는다.
- 설정 화면에는 알림 플레이북, 리그 전체 알림 토글, 프리셋 선택지, `요약 디테일`/`실시간 디테일` 세그먼트를 노출하지 않는다. 대신 `경기 전후`와 `경기 중` 항목별 토글을 모두 보여 사용자가 받을 moment를 하나씩 고르게 한다. 경기 상세 follow CTA는 설명 타일 없이 `푸쉬 중계 받기` / `푸쉬 중계 끄기` 단일 버튼으로 표시한다.
- 업데이트 소식 화면은 최근 버전별 섹션으로 표시하고 현재 설치 버전과 일치하는 섹션에 `현재 설치됨` 상태를 표시한다.
- 앱 업데이트 후 첫 접속에서는 현재 설치 버전의 업데이트 소식을 팝업으로 1회 표시한다. 최초 설치는 온보딩 완료 시 현재 버전을 기준선으로 기록해 첫 홈에 팝업을 띄우지 않는다. 기존 설치는 과거 seen-version 키가 없어도 신규 설치 기준선 표식이 없으면 업데이트 팝업을 보여준다.
- 앱 안의 업데이트 소식은 사용자가 체감하는 화면/알림/데이터 변화만 남긴다. 배포 checkpoint, 테스트, 서버/워크플로 세부는 `CHANGELOG.md`와 `docs/WORKLOG.md`에 분리한다.
- 업데이트 소식 문장은 `새로워졌어요:`, `고쳤어요:`, `빨라졌어요:`, `작게 다듬었어요:` 같은 유저용 분류로 시작해 작은 변경, 구체적인 버그 수정, 성능/안정성 개선까지 빠르게 훑을 수 있게 쓴다.

**아이콘 원칙**:
- 설정 상단 마이팀 액션은 custom glyph set을 사용한다.
- glyph는 20-21px, rounded cap/join, 상태색 16% fill과 35% border를 기본값으로 쓴다.

| 경기 종료 | 요약 | 마이팀 또는 선택 경기 | 전후 요약/실시간 모드에서 결과를 받는다. 꺼진 경우 team/GAME topic 모두 제외 |
| 라인업 | 요약 | 마이팀 또는 선택 경기 | 선발 라인업 공개를 경기 준비 신호로 발송 |
| 이닝 교대 | 라이브 갱신 | 마이팀 또는 선택 경기 | 실시간 모드에서 켜진 경우에만 일반 push topic에 포함 |
| 타석 | 바로 알림 | 마이팀 또는 선택 경기 | 새 타자가 들어서는 순간 문자중계 탭으로 바로 연결 |
| 야구 브리프 | 바로 알림 | 마이팀 | 월요일 주간 체크, 비경기일 일정/순위/기록 확인처럼 경기 이벤트가 아닌 야구 정보 확인 신호를 낮은 빈도로 발송 |

**설정 토글**:
- `경기 전후`: 선발 라인업 공개, 경기 시작/시작 임박, 경기 종료 결과, 야구 브리프를 개별 토글로 제공한다.
- `경기 중`: 득점, 안타, 홈런, 역전, 이닝 전환, 타석 변화를 개별 토글로 제공한다.
- 모든 moment를 끄면 상단 상태를 `모두 꺼짐`으로 표시하고, 마이팀 team topic 및 마이팀 외 selected-game GAME topic을 만들지 않는다.
- 전체 off 상태에서 한 항목을 다시 켜면 해당 moment의 기본 delivery를 복구한다. 경기 종료/라인업은 `summary`, 이닝 전환은 `liveOnly`, 나머지 항목은 `immediate`를 기본값으로 쓴다.
- 기존 설치나 저장값이 없는 사용자는 기존 수신 범위를 줄이지 않기 위해 모든 기본 moment를 켜진 상태로 해석한다. 내부 `summary_detail_level`/`live_detail_level` 값은 payload 호환성을 위해 남기되, 설정 UI의 사용자-facing 제어로 노출하지 않는다.
- 새 사용자 기본 범위는 마이팀 경기다. 마이팀 외 경기는 경기 상세의 follow action으로 `followedGameIds`에 들어온 경우에만 추가된다.

**Moment Preference 모델**:
```json
{
  "moment": "scoreChange",
  "delivery": "immediate",
  "scope": "myTeam",
  "surface": ["push"]
}
```

|------|-----|
| `moment` | `gameStartSoon`, `gameStart`, `scoring`, `hit`, `homerun`, `reversal`, `gameEnd`, `lineupOpened`, `inningChange`, `atBat`, `baseballInfo` |
| `delivery` | `immediate`, `summary`, `liveOnly`, `off` |
| `summaryDetailLevel` | `essential`, `standard`, `detailed` |
| `liveDetailLevel` | `essential`, `standard`, `detailed` |
| `scope` | `myTeam`, `selectedGame` |
| `surface` | `push`, `summary`, `liveActivity`, `liveUpdate`, `widget` |

**인터랙션**:
- 마이팀 탭 → 온보딩과 동일한 팀 선택 화면 (모달)
- 마이팀이 선택되지 않은 첫 실행에서는 OS push permission 을 요청하지 않는다
- 마이팀이 선택된 non-local 앱은 최초 1회 OS push permission 과 FCM registration sync를 자동 시도한다
- 사용자가 "푸쉬 중계 받기"처럼 명시적 action 을 선택했을 때도 OS permission / registration sync를 재시도할 수 있다
- 사용자가 푸시 알림 토글을 바꾸면 SharedPreferences의 boolean/delivery 값을 저장하고, 내부 호환용 `summary_detail_level`/`live_detail_level` 값을 현재 토글 조합에서 다시 계산한 뒤 `/push/register` 재동기화를 시도한다.
- `야구 브리프`가 바로 알림이면 앱은 `baseball_info_<팀>` topic을 구독한다. push data가 `type=baseball_info`이면 `route` 필드가 없어도 홈으로 진입한다.
- `followedGameIds`가 있으면 마이팀 외 일반 경기 event moment는 해당 moment가 켜져 있을 때만 `scoring_GAME_{gameId}`, `hit_GAME_{gameId}`, `game_start_soon_GAME_{gameId}`처럼 selected-game topic으로 추가한다. 선택한 경기가 마이팀 경기이면 같은 moment의 GAME topic을 만들지 않고 마이팀 team topic만 유지한다. `baseball_info`는 경기 event가 아니므로 GAME topic을 만들지 않는다.
- `바로 알림`은 push/topic 및 로컬 이벤트 알림 대상이 되고, `묶음 요약`은 summary preference 로 저장하며, `liveOnly`는 마이팀 외 선택 경기의 Live Activity / Android Live Update 중심 선호로만 사용한다
- 푸시/로컬 알림 클릭은 외부 URL을 직접 열지 않고 앱 내부 route로 변환한다. `lineupOpened` / `lineup_opened`는 `/game/{gameId}?tab=lineup`, 경기 시작 임박/경기 시작/득점/안타/홈런/역전/이닝 교대/타석은 `/game/{gameId}?tab=relay`로 진입한다. `baseball_info`는 홈으로 진입한다.
- 앱이 foreground 상태에서 원격 push를 받으면 OS foreground banner 대신 앱 내부 팝업을 표시한다. `보기`를 누르면 sanitized 내부 route로 이동하고, route가 없거나 지원하지 않는 값이면 알림함으로 fallback한다.
- 경기 상세를 보고 있는 동안 같은 경기의 중복 push 는 억제하고, Live Activity 또는 화면 내 상태 갱신으로 대체한다
- "푸쉬 중계 받기"는 알림 설정이 아니라 현재 경기 session 시작 action 이며, 경기 종료 또는 사용자의 "푸쉬 중계 끄기"로 종료한다
- local 모바일에서는 같은 Moment 규칙으로 로컬 알림을 생성하되, records/mock fallback 으로 불완전한 알림을 만들지 않는다
- 앱 종료 후에도 `바로 알림`과 iOS Live Activity / Dynamic Island를 갱신하려면 운영 백엔드가 KBO 상태를 polling하고 FCM/APNs로 발송해야 한다. Firebase만으로 경기 상태가 실시간 생성되지는 않는다.

### 2.8 앱 밖 경험 / 위젯 / Live Activity (Phase 1.5)

**목적**: 앱 밖 표면을 역할별로 분리해, 과한 push 없이 마이팀 상태를 빠르게 확인하게 한다.

| 표면 | 역할 | 시작 조건 | 표시 범위 |
|------|------|-----------|-----------|
| 바로 알림 | 즉시 알아야 하는 Moment | 사용자가 허용한 Moment | 득점/실점, 홈런, 동점/역전, 타석 |
| 묶음 요약 | 덜 긴급한 묶음 | 사용자가 summary 전달을 선택 | 경기 시작/종료, 라인업, 기록/예매성 정보 |
| 라이브 경기 알림 | 앱 밖 현재 경기 표면 | 마이팀 live/라인업 공개 예정 경기 자동 선택 또는 사용자의 "푸쉬 중계 받기" 선택 | 스코어, 이닝, 주자, B/S/O, 최근 변화 |
| 홈 위젯 | 주기적으로 보는 마이팀 상태판 | 위젯 설치 / 앱 데이터 sync | 다음 경기, 현재 경기, 경기 없음, stale 상태 |

**원격 갱신 계약**:
- iOS Live Activity는 앱에서 `ActivityKit` push token을 발급받아 `/api/push/live-activity/register`로 백엔드에 등록한다.
- iOS 17.2+에서는 앱 시작 시 `ActivityKit` push-to-start token도 `/api/push/live-activity/start-token/register`로 등록한다. backend scheduler는 마이팀 또는 사용자가 선택한 경기가 KST `startTime` 기준 10분 전 window에 들어오거나 `LIVE`가 되면 APNs `liveactivity` `event=start` payload로 앱을 열지 않아도 Live Activity / Dynamic Island를 시작한다. start token만 있고 같은 `installationId`의 FCM registration이 없거나, 알림 권한이 꺼져 있거나, 경기 시작 알림이 off이면 자동 시작하지 않는다.
- 라인업이 공개됐거나 시작 10분 전 window에 들어온 예정 경기는 Live Activity를 시작/유지할 수 있다. 이 상태에서는 content-state의 `isPregame=true`, `inning=경기전`, `awayRankText`/`homeRankText`를 사용하며 스코어 자리에는 점수 대신 각 팀 순위를 표시한다. 라인업 미공개 예정 경기는 시작 10분 전까지 Activity를 시작하지 않는다.
- 백엔드는 live 경기 중 5초 간격으로 scoreboard/relay sync를 실행하고, 등록된 ActivityKit token에 APNs `liveactivity` update payload를 보낸다.
- 같은 scheduler는 예정 경기의 KST `startTime` 기준 10분 전 window에서 `game_start_soon`을 한 번 발행하고, 대상 단말의 push-to-start token이 있으면 같은 window에서 Live Activity도 시작한다. 첫 관측은 baseline 저장만 하고, 예정 경기의 `lineupOpened`가 false에서 true로 바뀌면 `lineup_opened`, live 전환 이후 scoreboard diff로 `game_start`, `scoring`, `reversal`, `game_end`, `inning_change`, `at_bat`을 감지한다. 저장된 scoreboard baseline이 오래되었거나 해석 불가하면 missed moment를 보내지 않고 현재 state로만 재기준화한다. `reversal`은 이전 리더와 현재 리더가 모두 있고 리더가 바뀐 경우에만 발행하며, 0:0 같은 동점에서 첫 리더가 생긴 선취점은 `scoring`만 발행한다.
- scoreboard diff만으로 알 수 없는 `hit` / `homerun`은 같은 scheduler가 relay seq baseline을 따로 저장한 뒤 새 relay item의 `HIT` / `HOMERUN` event 또는 `안타` / `홈런` 텍스트를 감지해 FCM topic push로 발행한다. 저장된 relay baseline이 오래되었거나 해석 불가하면 현재 last seq로만 재기준화하고 밀린 `hit` / `homerun`은 보내지 않는다. relay의 `currentAtBat`에서 outs/baseState를 읽어 `현재 1사 1,2루` 같은 상황 텍스트를 함께 보내며, 경기 moment push copy는 `득점`, `안타`, `홈런`, `역전`, `이닝 교대`, `타석`처럼 짧은 사건명을 제목으로 쓰고 점수는 `스코어 4:3` 형식으로 분리한다. `홈런 발생`, `득점 발생`, `역전 상황입니다`처럼 설명식 표현은 쓰지 않는다.
- 경기 종료/취소/서스펜디드 상태에서는 APNs `end` event와 final content state를 보내고 token registry에서 세션을 제거한다. final content state는 `inning`에 최종 상태를 유지하되 batter/pitcher/pitchCount/B/S/O/situationText를 비워 마지막 타석을 현재 진행 중인 타석처럼 보이지 않게 한다. 일반 FCM push copy는 상태별로 분리해 `FINAL`만 `경기 종료` / `최종 스코어`를 쓰고, `CANCELLED`는 `경기 취소`, `SUSPENDED`는 `서스펜디드` 문구를 사용한다.
- FCM은 일반 push notification과 topic subscription에 사용한다. Backend가 보내는 일반 FCM message는 iOS APNs `apns-push-type=alert`, app bundle `apns-topic`, `aps.alert`, `aps.content-available=1`, `apns-priority=10`, default sound와 Android high priority / default sound를 함께 지정해 background/locked 상태에서 알림으로 즉시 노출되도록 한다. Dynamic Island content-state 갱신은 APNs ActivityKit 경로를 사용한다. 단말 receipt는 iOS delivery 상태에 따라 background handler, foreground handler, opened handler 중 하나가 `/api/push/receipt`를 호출해야 확인된다. 앱 foreground 상태에서는 Firebase foreground presentation alert를 끄고 앱 내부 팝업으로 보여준다.
- 홈 화면의 앱 내부 경기 이벤트 로컬 알림은 local 개발 모드에서만 처리한다. release/dev/TestFlight에서는 앱을 열거나 포커스했을 때 과거 scoreboard/relay diff를 로컬 알림으로 backfill하지 않고, 앱 밖 알림은 backend FCM/APNs 경로가 단독 책임진다. 로컬/회귀 확인 경로에서도 권한 off 동안 baseline은 계속 갱신하고, snapshot이 오래됐거나 알림 설정 signature가 바뀐 첫 tick은 알림 발행 없이 현재 상태만 저장한다. 회귀 확인용 빌드에서만 `ENABLE_LOCAL_GAME_EVENT_ALERTS=true` dart define으로 이 보조 로컬 알림 경로를 명시적으로 켤 수 있으며, relay 안타/홈런 본문은 backend와 같은 `현재 1사 1,2루` 상황 형식을 사용한다. 로컬 역전 알림도 이전 리더와 현재 리더가 모두 있고 리더가 바뀐 경우에만 발송한다.
- Live Activity content-state는 `batterAverage`, `pitcherEra`, `situationText`, `playText`, `isPregame`, `awayRankText`, `homeRankText`를 optional로 받을 수 있다. live 상태에서 `playText`가 있으면 하단 pill에 우선 표시하고, 없으면 `situationText`, 구장명 순서로 fallback한다. 타자/투수는 좌우 팀 패널에 직접 섞지 않고 중앙 matchup 라인에 모아 초/말 공격·수비 방향과 일치하게 표시한다. `batterAverage`는 relay currentAtBat의 시즌 타수/안타와 오늘 경기 완료 타석을 합산한 실시간 AVG를 우선 사용하고, 계산에 필요한 타수/안타가 없을 때만 KBO 표의 시즌 타율을 그대로 사용한다.
- 앱 foreground/resume/widget sync가 Live Activity를 직접 시작하거나 갱신하는 경로도 repository currentAtBat을 짧은 timeout으로 보강해 backend scheduler와 같은 타율/ERA/B-S-O 계약을 유지한다. 조회 실패 시에는 스코어/이닝만 갱신하고 빈 지표를 실제 0값처럼 표시하지 않는다.

**라이브 경기 알림 원칙**:
- 마이팀 live 경기와 마이팀 라인업 공개/시작 10분 전 예정 경기는 홈/위젯/재동기화 경로에서 기본 Live Activity target 으로 자동 선택한다. 이미 마이팀 외 경기를 선택한 상태여도 마이팀 후보가 있으면 마이팀 경기로 전환한다.
- 마이팀 외 경기는 사용자가 직접 "푸쉬 중계 받기"를 누른 경우에만 시작한다.
- 자동 선택은 follow session 저장, 가능한 live surface 동기화, backend push registration의 `followedGameIds` 갱신까지 수행한다. OS permission / push sync 는 마이팀 자동 등록 경로에서 최초 1회 시도하고, 홈/상세의 명시적 `푸쉬 중계 받기` action 에서도 재시도할 수 있다.
- 표시 데이터는 스코어, 이닝, 공격/수비, 주자, B/S/O, 마지막 변화, 마지막 갱신 시각, "그만 보기" action 까지로 제한한다.
- 현재 타석/투구 데이터가 없는 경우 B/S/O를 `0`으로 대체 표시하지 않고 숨긴다. 모르는 값과 실제 0카운트를 구분해야 한다.
- 경기 종료 후 최종 결과를 짧게 보여주고 종료한다.
- 시작 10분 전 window에 들어오지 않은 라인업 미공개 예정 경기, 뉴스, 광고, 일반 알림은 Live Activity / Android 라이브 경기 알림 표면에 넣지 않는다.
- Android는 `라이브 경기 알림` 진행형 ongoing notification을 표시하고, 같은 Live surface session의 스코어/이닝/갱신 시각을 업데이트한다.

**기술 구현**:
| 항목 | iOS | Android |
|------|-----|---------|
| 라이브 경기 알림 | ActivityKit / Live Activity | Android ongoing notification |
| Widget 프레임워크 | WidgetKit (Swift) | Glance API (Kotlin) / AppWidgetProvider |
| Flutter 연동 | `home_widget` 패키지 | `home_widget` 패키지 |
| 데이터 공유 | App Groups (UserDefaults) | SharedPreferences |
| 업데이트 주기 | Timeline (15분 최소) + 앱에서 강제 갱신 | WorkManager + 앱에서 강제 갱신 |
| 잠금화면 지원 | iOS 16+ (accessoryInline/Circular/Rectangular) | Android 14+ (Lock Screen Widgets) |

**현재 제공 위젯**:
- iOS `KBO Fans 경기판`: `systemSmall`, `systemMedium`, `systemLarge`, `accessoryInline`, `accessoryCircular`, `accessoryRectangular` family를 같은 scoreboard payload로 렌더링한다.
- Android `KBO 점수 위젯`: 기존 단일 경기 점수/상태 위젯이다.
- Android `KBO 경기판 위젯`: 오늘 경기 summary line을 최대 4개까지 표시하는 큰 홈 화면 위젯이다.
- 위젯 다양화를 위해 새 backend 상세 크롤링을 추가하지 않는다. 앱 foreground에서는 홈 scoreboard 전체 payload로 큰 위젯을 풍부하게 채우고, 백그라운드 refresh에서는 `/scoreboard/compact` 결과만으로 main 경기 중심 상태판으로 degrade 한다.

**위젯 표시 데이터**:
- 마이팀 경기: 양팀명, 스코어, 현재 이닝, 경기 상태, 마지막 업데이트 시각
- 경기 전: "14:00 예정" + 선발 투수
- 경기 중: 스코어 + 이닝 + 최근 업데이트. 투구별/타석별 변화는 앱 상세 또는 라이브 경기 알림 표면으로 연결
- 경기 종료: "경기종료" + 최종 스코어
- 경기 없음: "오늘 경기 없음 · 다음: 3.29(일)"
- 데이터가 오래된 경우: "업데이트 지연" 또는 "마지막 갱신 18:42" 를 명시

**위젯 원칙**:
- 위젯은 `실시간 중계`가 아니라 `상태판`이다.
- 소형 위젯은 하나의 다음/현재 마이팀 상태만 보여준다.
- 중형 위젯은 현재 경기 + 다음 경기 또는 마이팀 경기 + 리그 핵심 경기까지로 제한한다.
- 투구별, 타석별, 문자중계성 정보는 위젯에 넣지 않는다.
- 데이터 신선도 한계가 있는 플랫폼에서는 마지막 업데이트 시각을 함께 표시한다.
- live 경기 위젯은 2분, 그 외 상태는 15분 이상 갱신이 없으면 `업데이트 지연`을 표시한다.
- 위젯 탭은 현재 표시 중인 `widget_game_id`가 있으면 경기 상세로 진입한다. live 경기는 중계 탭, 종료/예정 경기는 스코어 탭을 기본으로 둔다.

## 5. Backend API 명세

이 섹션은 active FastAPI backend 계약이다. 화면 데이터를 backend-backed로 검증할 때는 앱에 `USE_BACKEND_API=true` 와 적절한 `API_BASE_URL` 을 함께 주입하고, push / Live Activity token registration 및 scheduler sync는 운영 backend endpoint와 별도로 readiness를 확인한다.

### Base URL
```
개발: http://localhost:8000/api
운영: TBD
```

### 공통 응답 형식
```json
{
  "success": true,
  "data": { ... },
  "error": null,
  "timestamp": "2026-03-28T14:30:00+09:00"
}
```

### 공통 에러 형식
```json

  "error": {
    "code": "GAME_NOT_FOUND",
    "message": "해당 경기를 찾을 수 없습니다"
  }

```

### 데이터 신선도 계층

| 계층 | 대상 데이터 | 서버 처리 방식 | 앱 처리 방식 |
|------|-------------|----------------|--------------|
| Live | 진행 중 경기 scoreboard, relay, 현재 타석, 당일 라인업 변경 | 짧은 TTL + adaptive polling, stale snapshot masking 금지 | fresh-first. API 실패 시 TTL 안의 로컬 API cache도 정상 데이터처럼 재사용하지 않음 |
| Warm Cache | 오늘 일정, 경기 단건 상세, 당일/직전 경기 박스스코어, 최근 팀 기록 | 메모리/Redis TTL 캐시 + 종료 직후 증분 갱신 | 화면 진입 전 prefetch, pull-to-refresh. 현재 날짜/월/시즌 실패는 오류로 노출 |
| Persisted Snapshot | 선수 과거 기록, 지난 경기 결과, 지난 날짜 순위, 시즌 누적 팀/선수 통계 | DB/스토리지에 정규화 후 저장, 재크롤링보다 snapshot 우선 | 로컬 캐시와 함께 즉시 렌더링, 필요 시 조용한 재검증 |

### 히스토리 데이터 저장 원칙

- 경기 종료 시점에 해당 경기의 박스스코어, 라인업, relay summary, 하이라이트 메타를 영속 저장한다.
- 선수 시즌 누적 기록과 최근 경기 로그는 경기 종료 이벤트를 기준으로 증분 업데이트한다.
- 순위는 하루 여러 번 snapshot 으로 저장하고, 과거 날짜 조회는 저장된 snapshot 을 우선 반환한다.
- 원천 KBO 응답이 수정될 가능성이 있으므로 당일/전일 데이터는 재검증 주기를 두고, 시간이 지난 히스토리 데이터는 낮은 빈도로만 재검증한다.
- 앱이 `지난 경기 / 지난 순위 / 선수 과거 기록`을 요청할 때는 원천 크롤링보다 저장된 정규화 데이터에서 먼저 응답해야 한다.
- backend 기록실 overview/leaderboard와 순위는 과거 시즌 snapshot이 있으면 crawler를 호출하기 전에 snapshot을 먼저 정규화해 반환한다. current 시즌은 기존처럼 fresh-first/fail-visible 이다.

### 앱 렌더링 정책

- 앱은 cold start 시 현재 날짜/월/시즌 데이터는 서버 최신 응답을 우선하고, API 실패 시 TTL 안의 로컬 API cache도 정상 데이터처럼 렌더링하지 않는다.
- 홈/일정/순위/기록실의 히스토리 데이터는 stale-while-revalidate 를 유지하되, current 데이터는 fresh-first/fail-visible 로 처리한다. 지난 경기/일정/순위 cache 는 30일, 과거 시즌 기록실/팀/선수 기록 cache 는 180일을 기준으로 조용한 재검증 빈도를 낮춘다.
- 로딩 스피너는 live 데이터가 실제로 비어 있을 때만 노출하고, 히스토리 데이터는 스냅샷이 있으면 skeleton 없이 바로 보여준다.
- 홈 첫 로딩은 오늘 스코어보드 별도 로컬 cache 를 먼저 렌더링하지 않고, 최신 API 응답 또는 명시적 오류 상태를 기준으로 전환한다.
- 홈이 이미 정상 스코어보드를 한 번 그린 뒤 resumed / timer refresh 가 실패하면, 저장 캐시를 새 정상 데이터처럼 쓰지 않고 화면에 보이던 같은 날짜 스코어보드만 유지한다. 이 경우 `다시 시도` 오류 화면은 첫 데이터가 전혀 없을 때만 노출하고, refresh 실패는 Dev Console 경고로 남긴다.
- 홈에서 경기 상세 진입 전 `gameProvider(gameId)` 갱신이 실패하거나 4초 안에 끝나지 않아도, 홈에 이미 표시된 `Game`이 있으면 그 정보를 `extra`로 넘겨 상세를 열고 상세 화면의 자체 refresh가 이후 최신화를 담당한다. 첫 상세 조회가 다시 실패하면 기존 경기정보와 `갱신 지연`/재시도를 함께 표시한다. 첫 진입 탭 provider는 병렬 warm-up으로 시작하지만 navigation gate에는 포함하지 않는다. 첫 화면부터 경기정보가 전혀 없는 cold 실패만 사용자 오류 상태로 둔다.
- 홈 secondary `/home` aggregate provider 는 scoreboard 첫 데이터 프레임 이후에만 구독해 첫 화면 렌더 전 부가 API fan-out 을 만들지 않는다.
- 홈 자동 refresh timer 는 refresh interval 과 scoreboard signature 가 바뀔 때만 재스케줄해 unrelated rebuild 로 live polling 이 지연되지 않게 한다.
- 홈 pull-to-refresh는 새 `scoreboardProvider` 응답이 끝날 때까지 indicator Future를 유지하고 API-backed 경로에서는 one-shot `forceRefresh=true`를 전달한다. refresh 중 이전 data를 표시하더라도 이를 fresh 완료로 간주해 다음 timer를 예약하지 않는다. 자동 갱신이 일시 실패하면 마지막 visible scoreboard를 유지한 채 다음 cadence에 다시 시도하고, 수동 요청과 겹친 자동 요청은 직렬 queue로 합친다. 앱 resume sync도 current scoreboard가 이미 loading이면 invalidate하지 않고 같은 Future를 기다린다.
- backend `/scoreboard/home`과 `/scoreboard/compact`는 홈/위젯 요약 표면 전용으로 schedule + main list 만 사용하고, 경기별 상세 스코어보드 크롤러는 full scoreboard 와 game detail 경로에서만 호출한다.
- backend current data routes 는 공용 runtime service singleton 을 공유해 `/scoreboard/home`, `/home`, game detail 계열이 같은 TTL cache 를 재사용한다. scoreboard service 내부에서도 같은 날짜의 schedule/main list 원천 결과를 짧은 TTL로 공유해 home/compact/game detail 진입이 같은 KBO 원천 호출을 반복하지 않게 한다.
- LIVE 요약 스코어보드는 KBO main list 의 유효한 득점을 schedule/detail fallback 의 0점보다 우선해, 진행 중 경기의 최신 score가 fallback 0:0에 막히지 않게 한다.
- 앱은 scoreboard payload의 팀 합계 H/E/B가 `null`이면 미수집 값으로 처리하고, 이를 `0` 기록처럼 렌더링하지 않는다.
- direct KBO mode 앱 라인업은 박스스코어 파생보다 KBO `GetLineUpAnalysis`를 우선 사용해 경기 전/진행 중 공개 라인업과 원천 제공 지표를 표시한다. `LINEUP_CK=false`이거나 응답이 비어 있으면 라인업 미공개 상태로 둔다.
- backend API와 direct KBO mode 박스스코어는 공식 타자/투수 rows가 없을 때 선발/현재 투수 이름만 합성해 0값 기록 카드로 표시하지 않고, 업데이트 전 상태를 유지한다.
- 앱 전역 Provider retry 는 비활성화한다. 화면은 API 실패를 자동 retry 뒤에 숨기지 않고 오류 카드, 빈 상태, 또는 Dev Console 로그로 명시한다.
- `allowCacheOnFailure` 기본값은 false 이며, 현재 날짜 스코어보드, 홈 aggregate, 경기 상세, relay, 박스스코어, 라인업, 현재 월 일정, 현재 시즌 순위/기록실/팀 기록/팀 선수/팀 스탯/선수 상세는 API 실패 시 fresh local API cache를 실패 fallback으로 쓰지 않는다.
- backend `/home` aggregate 는 현재/미래 날짜에서 schedule/standings/records overview 하위 호출 실패를 빈 섹션이나 placeholder 로 대체하지 않고 실패를 전파한다. 과거 날짜만 partial fallback 을 허용한다.
- backend current 스코어보드, 일정, 순위, 기록실 요약, 리더보드는 원천 실패 시 저장 snapshot 으로 정상 상태를 만들지 않는다. 과거 날짜/시즌/월 snapshot 은 저장본 우선 정책을 유지한다.
- backend 기록실 요약과 리더보드는 KBO 응답 row 순서에 의존하지 않고 rank 오름차순으로 정규화한 뒤 앱에 전달한다.
- 현재/진행 예정 경기 상세의 박스스코어, 라인업, LIVE relay 는 원천 실패 시 저장 snapshot 또는 요약 payload 로 정상처럼 대체하지 않는다. 박스스코어의 adjacent game id fallback 은 과거 경기 canonical id 보정에만 허용하고, current/live 경기는 비어 있으면 `officialAvailable=false` 상태를 노출한다.
- live 경기의 공식 박스스코어 rows가 비어 있어도 KBO main list가 현재 타자/투수 context를 제공하면 `/game/{gameId}/boxscore`는 `officialAvailable=false`, `liveContextAvailable=true`, `source=live_context`를 반환할 수 있다. 이 payload는 snapshot으로 저장하지 않고 앱에서는 `실시간 기록 추적` 상태로 렌더링한다.
- LIVE 경기 상세는 탭 전환 시 현재 보이는 탭의 최신 데이터를 즉시 갱신한다. 스코어 탭은 경기 상세, 문자중계 탭은 relay, 박스스코어 탭은 boxscore, 라인업 탭은 lineup provider를 타이머 tick 전에도 refresh한다.
- 경기 상세 자동 갱신은 완료 시점 기준 one-shot timer로 재예약한다. 이미 loading/refreshing인 visible provider를 timer가 다시 invalidate하지 않으며, 자동 갱신 중 사용자가 pull-to-refresh를 요청하면 현재 요청 완료 뒤 force refresh를 정확히 한 번 더 실행한다. 일시적 relay refresh 실패에는 마지막 정상 문자중계를 유지한다.
- 라인업 탭의 일시적인 timeout/connection 실패는 저장 snapshot으로 정상처럼 대체하지 않고, `라인업을 다시 불러오고 있습니다` 상태와 자동 갱신 안내를 보여준다. 개발용 `DioException` 전문은 사용자 화면에 노출하지 않는다.
- 경기 상세 image prefetch는 fade-in/placeholder 연출로 문제를 숨기지 않고, 박스스코어 row, 라인업 starter/row, relay current-at-bat/최근 item에 필요한 선수 이미지 URL을 dedupe한 뒤 KBO 선수사진 전용 cache manager와 `precacheImage` 경로까지 태운다. 홈/일정에서 상세로 이동할 때는 `gameProvider(gameId)`만 navigation gate에 포함하고, 첫 진입 탭 provider와 선수 이미지 cache warm-up은 background로 이어간다. 박스스코어 row는 backend/app 계약상 `playerId`/`imageUrl`을 보존하고, row-native 값이 없을 때만 팀 선수 목록 이름 매칭으로 보강한다.

**Live Activity 운영 계약**:
- `register`: 앱/iOS native가 `gameId`, `activityId`, `activityPushToken`을 등록한다.
- `start-token/register`: iOS 17.2+ 앱이 push-to-start token과 stable `installationId`를 등록한다. scheduler는 이 token을 같은 설치 id의 push registration과 매칭해 마이팀/선택 경기가 KST `startTime` 10분 전 window에 들어오거나 LIVE로 전환될 때 APNs `event=start`를 보낸다. 같은 game/token 조합은 한 번만 발송하고, active Live Activity가 이미 같은 설치 id에 등록돼 있으면 다시 시작하지 않는다.
- `update`: 내부 운영 도구나 worker가 특정 `gameId`의 `content-state`를 APNs로 발송한다.
- `sync-scoreboard`: backend scheduler가 scoreboard와 live relay를 읽고 등록된 Live Activity 세션에 update/end를 발송한다. 일반 푸시 등록 기기가 있으면 예정 경기 `game_start_soon` / `lineup_opened`, 10분 전 push-to-start Live Activity start, scoreboard diff 기반 FCM moment push, relay diff 기반 `hit` / `homerun` push도 발행한다. 단, 저장된 scoreboard/relay baseline이 오래되었거나 해석 불가하면 밀린 moment를 보내지 않고 현재 state/last seq로만 재기준화한다. long-running sync worker는 KST `PUSH_BASEBALL_INFO_SMART_DAILY_TIMES` 슬롯마다 `baseball_info` smart daily 브리프도 하루 한 번씩 계획한다. `/home`, `/scoreboard*`, `sync-scoreboard`에서 `date`를 생략하면 서버 로컬/UTC 날짜가 아니라 `Asia/Seoul` KBO 경기일을 기본값으로 사용한다. 운영에서는 `PUSH_SYNC_SECRET`으로 보호한다.
- 일반 경기 event push는 backend가 매 moment마다 원정팀 topic, 홈팀 topic, 경기별 topic(`{moment}_GAME_{gameId}`)으로만 발송한다. 앱은 `myTeam`, `followedGameIds`, `notifications.deliveryModes`, `notifications.summaryDetailLevel`, `notifications.liveDetailLevel`을 기준으로 필요한 topic을 구독한다. 마이팀 team topic과 selected-game GAME topic은 모두 enabled이고 delivery가 `off`가 아닌 game moment만 포함한다. 선택 경기가 마이팀 경기이면 같은 moment의 GAME topic을 만들지 않고 team topic만 유지해 중복 수신을 피한다. legacy `allGames=true`가 남아 있어도 경기 moment `*_ALL` topic은 구독하거나 발송하지 않는다.
- `test`: 운영자가 특정 FCM token 또는 topic으로 테스트 알림을 발송한다. 운영에서는 `PUSH_SYNC_SECRET`으로 보호한다. `hit_GAME_20260620HTKT0`처럼 GAME topic으로 발송하면 receipt 확인을 위해 `type`, `gameId`, `topic`, 상세 `route` data를 함께 싣는다. 반복 push 발송 확인은 `PUSH_SYNC_SECRET=<...> ./scripts/push-test-notification.sh --topic <topic>` 또는 `--token <fcm-token>`으로 수행한다. 로컬에 secret을 두지 않는 경우 `Push Test Notification` GitHub Actions workflow 또는 `./scripts/github-push-test-notification-run.sh --topic <topic> --watch`로 GitHub secret 컨텍스트에서 실행한다.
- `test-device`: 앱 API 진단 화면에서 자기 기기에 원격 테스트 push를 요청하는 self-test endpoint다. 앱은 먼저 FCM token을 `/push/register`로 등록한 뒤 `deviceToken`만 보낸다. backend는 registry에 이미 저장된 token에만 고정 문구와 `/diagnostics` route를 담아 발송하며, 앱 번들에 `PUSH_SYNC_SECRET`을 넣지 않는다.
- `receipt`: 앱이 원격 push를 foreground/background/opened 상태로 처리하면 현재 FCM `deviceToken`, `messageId`, `source`, `type`, `gameId`, `route`, 제한된 data 단서를 backend에 보고한다. backend는 registry에 이미 저장된 token만 기록하고 token 원문은 최근 receipt 요약에 노출하지 않는다. 이 endpoint는 앱 번들에 `PUSH_SYNC_SECRET`을 넣지 않기 위해 secret을 요구하지 않는다.
- `baseball-info`: 운영자가 `weekly_check`, `off_day`, `game_day`, `records_check`, `lineup_day`, `rival_watch` 같은 야구 정보 확인 push를 보낸다. topic/token/teamId를 지정할 수 있고, 지정하지 않으면 10개 구단 `baseball_info_<팀>` topic과 `baseball_info_ALL`로 발송한다. `teamId`를 지정하면 알림 copy는 `LG 트윈스 기록실`, `LG 트윈스 경기일 체크`처럼 팀 이름 기준으로 구체화한다. `gameId`, `matchup`, `startTime`, `stadium`을 함께 지정하면 경기 전/경기일 copy는 `롯데 vs 두산 경기 전 체크`, `18:30 · 잠실`처럼 실제 매치업 context를 우선 표시하고 route도 해당 경기 상세로 연결한다. `dryRun=true`이면 Firebase 발송 없이 title/body/data/targets 미리보기만 반환한다. 운영에서는 `PUSH_SYNC_SECRET`으로 보호한다.
- `python -m kbo_fans_backend.scheduler.baseball_info`: 수동 운영/cron용 CLI다. `--date`만 주면 KBO 경기일 기준 월요일에는 `weekly_check`를 발송하고, 다른 요일에는 자동 발송하지 않는다. `--kind records_check`처럼 명시하면 요일과 무관하게 해당 야구 브리프를 보낸다. 운영 전에는 `--dry-run`으로 topic과 copy를 확인한다. `--smart-daily`를 쓰면 해당 날짜 scoreboard를 읽어 팀별로 오늘 경기가 있으면 `game_day`, `--now-time HH:MM` 기준 경기 시작 3시간 이내이면 `lineup_day`, 이미 종료된 경기만 있으면 `records_check`, 마이팀 경기는 없지만 리그 경기가 있으면 `rival_watch`, 전체 리그가 쉬면 `off_day`를 자동 선택하고, 리그 전체 구독자용 `baseball_info_ALL`도 함께 계획한다. 팀별 경기 전/경기일 plan은 `gameId`, `matchup`, `startTime`, `stadium`을 push service에 전달해 상대팀이 빠진 팀명-only 알림을 피한다. ECS sync worker 기본 슬롯은 `09:30,16:00,22:30` KST이며 `PUSH_BASEBALL_INFO_SMART_DAILY_TIMES=off`로 끌 수 있다.
- `resubscribe-topics`: registry에 저장된 FCM device registration을 현재 push schema로 다시 해석해 Firebase topic을 재구독한다. `at_bat`, `game_start_soon`, `hit`, `*_GAME_{gameId}`처럼 새 moment topic을 추가한 뒤 기존 TestFlight 설치자의 topic membership을 보정할 때 사용한다. 운영에서는 `PUSH_SYNC_SECRET`으로 보호한다.
- `config-status`: Firebase Admin, APNs Auth Key, registry path, scheduler secret 설정 상태를 secret 원문 없이 반환한다. `FIREBASE_SERVICE_ACCOUNT_JSON`/`APNS_AUTH_KEY_P8` env secret 방식과 `*_PATH` 파일 방식을 모두 진단하며, scheduler heartbeat는 `scheduler.lastSyncAt` / `scheduler.lastSyncDate`로 노출한다. registry 진단에는 device token 원문 없이 `registeredDeviceCount`, `followedGameCount`, `activeLiveActivityGameCount`, `topicCounts`, `myTeamCounts`, `deviceSummaries`, `pushReceiptCount`, `recentPushReceipts`를 포함한다. `deviceSummaries`는 token suffix, installation id suffix, platform, myTeam, followedGameIds, topicCount, updatedAt, topicsUpdatedAt, notificationsAllowed, authorizationStatus, apnsTokenReady만 노출해 앱 설치 최신성, 서버 topic 재동기화, 실제 알림 권한/APNs 준비 상태를 분리해서 본다. 운영에서는 `PUSH_SYNC_SECRET`으로 보호한다. 실제 단말 receipt 확인은 `PUSH_SYNC_SECRET=<...> ./scripts/push-receipt-status.sh --expect-receipt --game-id <gameId> --type <type>`로 조회하고, 로컬에 secret이 없으면 `Push Receipt Status` GitHub Actions workflow 또는 `./scripts/github-push-receipt-status-run.sh --expect-receipt --game-id <gameId> --type <type> --watch`를 사용한다.
- `content-state` 필드명은 Swift `KboFansScoreAttributes.ContentState`와 동일한 camelCase를 유지한다. 기본 스코어/이닝/선수/카운트 필드 외에 하단 상황 표시용 `situationText`, `playText`를 optional로 보낼 수 있다.

**마이그레이션 메모**:
- 기존 boolean 기반 `notifications` body 는 앱 업데이트 전환 기간 동안만 호환 입력으로 유지할 수 있다.
- `installationId`는 앱 설치 단위의 stable id다. 같은 설치에서 FCM token이 바뀌면 backend는 같은 `installationId`를 가진 이전 token registration을 제거해 팔로우 경기 push 대상이 stale token에 남지 않도록 한다.
- `momentPreferences` / `notifications.deliveryModes` / `notifications.summaryDetailLevel` / `notifications.liveDetailLevel` 는 브리프, 마이팀 기본 경기, 마이팀 외 selected-game follow, 향후 운영 확장을 위한 선호 입력으로 유지한다. 마이팀 team topic과 selected-game GAME topic은 enabled이고 delivery가 `off`가 아닌 game moment만 포함한다. legacy `allGames=true`는 경기 moment topic 계산에서 무시한다.
- `followedGameIds` 는 알림 설정이 아니라 현재 Live surface session 을 표현한다. 홈의 마이팀 live/라인업 공개 예정 경기 자동 target 과 사용자가 직접 시작한 selected-game follow 를 모두 포함하며, 앱은 follow 시작/종료 직후 `/push/register`를 다시 호출해 registry를 정리한다.
- `followedGameIds`가 비어 있어도 사용자는 켜진 마이팀 event topic을 구독한다. `followedGameIds`가 있으면 마이팀 외 경기 event moment는 enabled 상태인 selected-game `*_GAME_{gameId}` 범위로 추가하고, `summary` / `liveOnly` delivery도 GAME topic에는 포함한다. 사용자가 `off`로 끈 항목은 마이팀 team topic과 마이팀 외 selected-game GAME topic에서 모두 제외된다. 야구 브리프처럼 경기 단건에 속하지 않는 정보성 push는 마이팀 topic을 따른다.

## 7. 경기 상태 코드

| 상태 | 코드 | 설명 |
|------|------|------|
| 경기 예정 | `SCHEDULED` | 경기 시작 전 |
| 경기 중 | `LIVE` | 진행 중 |
| 경기 종료 | `FINAL` | 정상 종료 |
| 우천취소 | `CANCELLED` | 기상 등 사유로 취소 |
| 서스펜디드 | `SUSPENDED` | 일시 중단 (차후 속행) |

표기 정책:
- 일정 화면 카드 상태 배지는 `경기 전`, `경기 중`, `경기 종료`, `우천취소` 또는 `경기 취소`, `서스펜디드`를 사용한다.
- 상세 화면 스코어버그 중앙 보조 문구는 루상 다이아몬드 위에 이닝(`4회초`, `연장 10회말`, 종료 경기의 `9회` 등)을 우선 노출한다. 종료 경기 상단에서는 `경기 종료`, 시작 시각, `최종 기록`을 반복 표시하지 않는다.
- `CANCELLED`는 `statusLabel` 또는 KBO `CANCEL_SC_NM`에 `우천취소` 같은 취소 사유가 있으면 해당 문구를 우선 표시하고, 사유가 없으면 `경기 취소`를 기본 문구로 사용한다.
- 연장전은 별도 상태 코드가 아니라 이닝 문자열(`연장 10회초`, `10회말`)로 표현한다.
- `SUSPENDED`는 서스펜디드 경기로 표기하고, 문자중계/상세는 재개 전 기준 안내 문구를 우선 노출한다.
